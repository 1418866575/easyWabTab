Postman 指南

从「填 URL 点 Send」到「把接口测试跑进流水线」——一份能随时翻阅的中文手册。内容基于 Postman 官方文档翻译版（postman.xiniushu.com）整理，并补充了截至 2026 年 v12 版本的最新能力。

Postman v12.x（2026） REST / GraphQL / gRPC / WebSocket / SOAP Agent Mode · AI 原生 最后更新：2026-09

1Postman 是什么

Postman 是一个 API 平台，用来设计、调试、测试、文档化和监控 API。它最早以「图形化的 HTTP 请求构造器」被大家熟知，但现在已经覆盖了 API 的整个生命周期。

发送请求

支持 REST、GraphQL、gRPC、WebSocket、Socket.IO、SOAP 等协议，可配置参数、Header、Body、Cookie、认证。

编写脚本

基于 Node.js 运行时，在请求前后执行 JavaScript，做断言、数据传递、动态签名。

使用集合

把请求分组保存，批量运行、定时运行、在 CI/CD 中运行。

Mock 与监控

用 Mock Server 模拟未完成的接口；用 Monitor 定时拨测线上接口健康度。

协作与治理

团队工作空间、评论、角色权限、API Governance 规范检查。

CLI / CI

Newman 与 Postman CLI 让集合在流水线里跑起来，产出报告。

典型工作流

工作流
设计 API（Schema） → 生成 Mock → 前后端并行开发
        ↓
    在 Postman 里调试请求 → 写测试断言
        ↓
    存为集合 + 环境（dev / test / prod）
        ↓
    Collection Runner 跑数据驱动测试
        ↓
    Newman / Postman CLI 接入 CI/CD → 失败即阻断
        ↓
    Monitor 定时监控线上 + 报告看板

22026 最新版本新特性

Postman 在 2026 年完成了「AI 原生 + 代理化（Agentic）」的大版本升级，当前桌面端版本号已到 v12.25+。以下是值得关注的变化：

Agent Mode（代理模式）

Postman 早期 AI 助手 Postbot 已在 2026 年 1 月被平台级 AI 能力取代。新的 Agent Mode 不只是问答，它能理解工作区上下文，直接替你动手：发请求、修错误、改测试、生成 Mock、生成客户端代码。用自然语言描述目标（例如「测试从登录到下单的完整流程」），它会自动串联多个请求、生成断言并执行。

3安装与界面速览

获取方式

  • 桌面端（推荐）：Windows / macOS / Linux，官网 postman.com/downloads
  • Web 端：浏览器访问 web.postman.com，无需安装
  • CLI：Postman CLI（新版，推荐）与 Newman（老牌命令行运行器）
桌面端 vs Web 端

Web 端不能发 localhost 本机请求（需配合 Postman Desktop Agent 或 CLI 的隧道），也不支持部分本地文件相关的 Body 类型。日常调试本机服务建议用桌面端。

4发送第一个请求

  1. 打开 Postman，选择 New → HTTP，或点标签栏的 + 打开新标签页。
  2. 方法保持 GET，URL 填入 Postman 官方示例接口：https://postman-echo.com/get
  3. 点 Send。
  4. 下方响应区会出现 JSON、状态码、耗时、大小。
  5. 点 Save，给请求起个名字并选择一个集合保存（可新建）。
响应示例
{
  "args": {},
  "headers": {
    "host": "postman-echo.com",
    "user-agent": "PostmanRuntime/7.39.0",
    "accept": "*/*"
  },
  "url": "https://postman-echo.com/get"
}
练习接口推荐

https://postman-echo.com/get（GET）、/post（POST，回显 body）、/delay/3（延迟响应）、/status/500（指定状态码）、/basic-auth（基础认证）。用它练手不用自己搭服务。

5构建请求

5.1 设置 URL

URL 一般由「基础地址 + 路径」组成，例如 https://postman-echo.com/get 中，https://postman-echo.com 是基础地址，/get 是端点路径。

  • 不写协议时 Postman 会自动补 http://。
  • 输入时会有历史地址下拉自动补全。
  • 路径参数直接写进 URL：/customer/:id，Postman 会同步到 Params 标签页。

5.2 请求方法

方法用途是否有 Body
GET查询数据（默认）通常没有
POST新增资源有
PUT整体替换资源有
PATCH局部更新字段有
DELETE删除资源可选
HEAD / OPTIONS取响应头 / 查询支持的方法没有

Postman 还支持自定义方法：在方法下拉框里直接编辑方法名并保存即可。

5.3 发送参数

  • 查询参数 Query：追加在 URL 末尾，?id=1&type=new。可在 URL 或 Params 标签页填写，两处同步。
  • 路径参数 Path：URL 中用 : 前缀声明，如 /customer/:id。
参数不会自动 URL 编码

选中文本右键 → EncodeURIComponent 手动编码。若服务器实现特殊，可在 Settings → 自动编码 URL 关闭自动编码。

5.4 请求体 Body（5 种类型）

类型适用场景自动设置 Content-Type
none不需要正文（默认）—
form-datamultipart/form-data，网页表单、文件上传是
x-www-form-urlencodedURL 编码的键值对表单是
raw任意文本：JSON / XML / HTML / JS / Text是（按所选格式）
binary图片、音视频、文件二进制否（需手动）
GraphQLGraphQL 查询与变量是
小技巧

JSON body 里可以写 // 单行注释 和 /* 多行注释 */，发送时会被自动剥离，方便调试时临时注释字段。格式化 JSON/XML 快捷键：Ctrl+Alt+B（macOS ⌘+Option+B）。

5.5 请求头 Headers

  • 输入时会自动提示常用头（如 Content-Type）。
  • 灰色的是 Postman 自动生成头，点 隐藏/显示 可查看，悬停可看到生成原因。
  • 取消勾选可停用自动头；想覆盖则取消勾选后手动加一条同名头。
  • 常用头组合可存为 Header Presets（Headers → Presets → Manage Presets）。

5.6 Cookie

点 Send 下方的 Cookies 可管理该域名的 Cookie；全局管理在 Settings → Cookies 或请求页的 Cookie 管理入口。

5.7 其他协议

GraphQL

Body 选 GraphQL，填 Query 与 Variables；绑定 API Schema 后支持字段自动补全。

gRPC

导入 .proto 生成方法列表，支持一元/客户端流/服务端流/双向流；脚本挂在 Before invoke / After response。

WebSocket / Socket.IO

建立长连接后收发消息，可保存消息为示例。

SOAP

选 raw + text/xml，Body 里填 SOAP 信封。

6认证与授权

在 Authorization 标签页配置，Postman 会把凭证自动放到请求对应位置（Header / Query / Body）。集合级别设置一次，子请求选 Inherit auth from parent 即可继承——这是最省事的做法。

类型说明典型字段
No Auth无需认证—
Bearer TokenJWT / OAuth2 令牌，最常见token
Basic Auth用户名密码，自动 Base64username / password
API Key放在 Header 或 Query 参数key / value / in
OAuth 1.0老式签名认证consumer key/secret、token/secret、签名方法
OAuth 2.0可自动获取 token（Authorization Code / Client Credentials / Password / Implicit）Access Token URL、Client ID/Secret、Scope、State
Digest / Hawk / NTLM / AWS Signature特殊场景签名认证按向导填写
推荐实践：脚本自动续 token

把 token 存成环境变量，在集合的 Pre-request Script 里判断是否过期，过期就重新获取。示例见 第 12 章。

安全提醒

密码、密钥、token 这类敏感值，请把变量类型设为 secret，并对环境变量谨慎使用 Persist（会把本地当前值同步给团队）。

8变量与环境变量

变量让你不必把值到处硬编码，用 {{变量名}} 引用，请求运行时替换为当前值。可用于 URL、Params、Headers、Authorization、Body 和 Header 预设。

8.1 五种作用域与优先级

作用域（由宽到窄）
Global 全局        → 整个工作空间可见
Collection 集合    → 集合内所有请求可见，不随环境切换
Environment 环境   → 需先选中某个环境，一次只能激活一个
Data 数据          → 来自 CSV / JSON 数据文件，运行结束即失效
Local 局部         → 脚本内临时变量，请求/集合运行结束即失效

优先级：Local > Data > Environment > Collection > Global
（同名变量，范围越窄越优先）

8.2 在脚本中读写变量

JavaScript
// 读取（pm.variables.get 自动按优先级取最窄作用域）
pm.variables.get("base_url");
pm.globals.get("g_key");              // 全局变量
pm.collectionVariables.get("c_key");  // 集合变量
pm.environment.get("token");          // 环境变量
pm.iterationData.get("username");     // 数据文件变量

// 写入
pm.globals.set("g_key", "value");
pm.collectionVariables.set("c_key", "value");
pm.environment.set("token", json.token);
pm.variables.set("local_key", "value");   // 局部变量

// 删除
pm.environment.unset("token");

// 对象要序列化后存储（变量底层都是字符串）
pm.environment.set("user", JSON.stringify({id: 1, name: "Tom"}));
const user = JSON.parse(pm.environment.get("user"));

8.3 动态变量（内置随机数据）

Postman 内置了一批动态变量，每次请求都会生成新值，非常适合造测试数据。

常用动态变量
{{$guid}}             // v4 风格 GUID，如 "3a7d-4f2b-..."
{{$timestamp}}        // 当前 Unix 时间戳（秒）
{{$isoTimestamp}}     // ISO 格式时间，如 2026-09-22T07:13:17.000Z
{{$randomInt}}        // 0~1000 随机整数
{{$randomUUID}}       // UUID
{{$randomEmail}}      // 随机邮箱
{{$randomPhoneNumber}}// 随机手机号
{{$randomFirstName}} / {{$randomLastName}} / {{$randomFullName}}
{{$randomCompanyName}} / {{$randomCity}} / {{$randomCountry}}
{{$randomAlphaNumeric}} / {{$randomHexColor}}
在脚本里用动态变量

用 pm.variables.replaceIn('{{$randomFirstName}}') 获取替换后的实际值。

8.4 secret 类型变量

环境变量和全局变量可设置类型为 secret，其初始值与当前值对所有工作空间成员显示为掩码，降低误泄风险。设置方法：环境编辑器中点击变量类型下拉 → 选 secret。

8.5 Initial Value 与 Current Value

  • Initial Value：随集合/环境共享同步的值，提交进版本管理的值。
  • Current Value：仅本地生效，不会同步给团队。
  • 想让本地值同步给团队：点变量旁的 Persist（或 Persist All）。
  • 想丢弃本地改动回到共享值：点 Reset。

8.6 变量未解析（红色）

Postman 会把找不到的变量标红。常见原因：变量不在活动作用域、改了没保存、所在环境未激活、环境里变量被关掉。悬停红色变量可以看到修复入口。

9集合 Collections

集合是一组保存的请求。历史记录（History）里找请求在小规模时还行，请求一多就必须靠集合来组织。

9.1 基本操作

  • 创建：侧边栏 Collections → + 或 New → Collection。
  • 文件夹：集合内右键 → Add Folder，可按模块/业务分组。
  • 集合级配置：选中集合可编辑 Variables、Authorization、Pre-request Script、Tests，对集合内所有请求生效。
  • 导入导出：集合右侧 ... → Export 导出 JSON（v2.1 格式）；Import 支持 Postman 集合、cURL、OpenAPI/Swagger、WSDL、RAML、GraphQL Schema。
  • Fork / Merge：团队协作时可 fork 后提合并请求。

9.2 集合版本与文档

集合可以发布文档（Publish Docs），默认私有，也可发布为公开页面供浏览器访问。文档里会带上请求描述、参数说明、示例响应以及测试脚本。

团队约定建议

① 每个系统一个集合；② Base URL、token 一律用变量；③ 集合级统一配 Authorization；④ 集合描述里写清环境切换方式；⑤ 请求名用「模块-动作」命名，如「用户-登录」。

10脚本编写入门

Postman 内建基于 Node.js 的运行时（Postman Sandbox），可以在两个时机插入 JavaScript：

位置执行时机典型用途
Pre-request Script
预请求脚本		请求发送之前生成时间戳/签名/random 值、读取并注入 token、动态改 URL 和 Body
Tests
测试脚本		收到响应之后断言状态码/字段/性能、提取响应数据写入变量、控制下一步请求

10.1 脚本可以挂在哪一层

集合、文件夹、单个请求都能挂脚本，粒度由粗到细。

执行顺序
单个请求：  请求级 Pre-request  →  发请求  →  请求级 Tests

集合运行时（每个请求都走一遍）：
  集合级 Pre-request
    → 文件夹级 Pre-request
      → 请求级 Pre-request
        → 发送请求
      → 请求级 Tests
    → 文件夹级 Tests
  → 集合级 Tests
记住一句话

「外层的先跑，内层的后跑；外层包住内层」。想对全集合统一加签名或统一校验状态码，就写在集合级脚本里，别一个请求一个请求地抄。

10.2 预请求脚本示例

JavaScript · 生成签名与随机参数
// 1) 生成时间戳和随机串，写入变量供请求引用
pm.environment.set("timestamp", Date.now().toString());
pm.environment.set("nonce", Math.random().toString(36).slice(2, 10));

// 2) 接口签名：timestamp + nonce + body 做 MD5（CryptoJS 内置可用）
const CryptoJS = require("crypto-js");
const secret = pm.environment.get("app_secret");
const raw = pm.environment.get("timestamp") + pm.environment.get("nonce") + pm.request.body.raw;
pm.environment.set("sign", CryptoJS.MD5(raw + secret).toString().toUpperCase());

// 3) 动态修改请求头
pm.request.headers.add({ key: "X-Request-Id", value: "{{$guid}}" });

// 4) 动态改 URL 的查询参数
pm.request.url.query.add({ key: "t", value: Date.now().toString() });

10.3 测试脚本示例

JavaScript · 基础断言 + 提取 token
// 状态码
pm.test("状态码为 200", function () {
    pm.response.to.have.status(200);
});

// 解析响应
const json = pm.response.json();

// 业务码与字段
pm.test("业务成功", () => pm.expect(json.code).to.eql(0));
pm.test("返回 data 不为空", () => pm.expect(json.data).to.be.an("object"));

// 把 token 存起来给后续请求用（关键！链式调用靠它）
if (json.data && json.data.token) {
    pm.environment.set("token", json.data.token);
}

// 性能断言
pm.test("响应时间小于 500ms", () => pm.expect(pm.response.responseTime).to.be.below(500));

// 响应头
pm.test("Content-Type 为 JSON", () => {
    pm.expect(pm.response.headers.get("Content-Type")).to.include("application/json");
});
调试脚本

12.5 自动续期 token（集合级）

JavaScript · 集合 Pre-request Script
const token = pm.environment.get("token");
const exp   = Number(pm.environment.get("token_exp") || 0);
const needRefresh = !token || Date.now() > exp;

if (needRefresh) {
    pm.sendRequest({
        url: pm.environment.get("base_url") + "/auth/login",
        method: "POST",
        header: { "Content-Type": "application/json" },
        body: {
            mode: "raw",
            raw: JSON.stringify({
                username: pm.environment.get("username"),
                password: pm.environment.get("password")
            })
        }
    }, (err, res) => {
        if (err || !res.code || res.code < 200 || res.code >= 300) {
            console.error("获取 token 失败", err);
            return;
        }
        const j = res.json();
        pm.environment.set("token", j.data.token);
        pm.environment.set("token_exp", Date.now() + j.data.expiresIn * 1000);
    });
}

13工作流与数据驱动

13.1 控制请求执行顺序

默认按集合里的顺序从上到下执行，用 pm.execution.setNextRequest 可以跳转或终止。

JavaScript
// 跳到指定请求（名字必须与集合中的请求名完全一致）
pm.execution.setNextRequest("下单-创建订单");

// 根据条件分支
if (pm.response.code !== 200) {
    pm.execution.setNextRequest("告警-通知");   // 出错走告警分支
} else {
    pm.execution.setNextRequest("查询-订单详情");
}

// 结束本次集合运行
pm.execution.setNextRequest(null);
注意

① 参数是请求名称不是 URL；② 只对集合运行（Runner / Newman / Monitor）生效，单请求点 Send 无效；③ setNextRequest 只影响「本轮之后的下一个请求」，不影响当前请求后面的默认顺序之外的逻辑；④ 跳转目标必须在同一集合内。

13.2 数据驱动（CSV / JSON）

准备一份数据文件，每行一组入参，Runner 会按行数迭代执行集合。

14Collection Runner

集合运行器用来按顺序批量跑集合，并汇总测试结果。

  1. 打开集合 → 右侧 Run（或底部 Runner）。
  2. 选择要跑的请求（可全选/部分）。
  3. 选择环境；需要数据驱动则上传 CSV/JSON 数据文件并设置迭代次数。
  4. 可设置 Delay（请求间隔）、Iterations（迭代次数）、Persist responses（保存响应便于回看）。
  5. 点 Run，查看每个请求的通过/失败、耗时、断言明细。
Runner 结果怎么看

左侧是请求列表，右侧是每轮的结果；红色为失败点。失败时优先看 Test Results 的断言消息，再看 Console 里的实际报文。AI 调试（v12）还能直接在运行结果里给出根因分析和修复建议。

15Mock Server 模拟服务

后端接口还没写好？用 Mock Server 先造一个假接口，前端就能并行开发。

  1. 集合右侧 ... → Mock Collection（或侧边栏 Mock Servers → New）。
  2. 配置 Mock 名称、环境、是否私有（私有需 API Key 才能访问）。
  3. 创建后得到一个 Mock URL，如 https://xxxx.mock.pstmn.io。
  4. 在集合里为每个请求保存 Example（示例响应），Mock 会按请求方法和路径返回对应示例。
  5. 没有匹配到示例时，Mock 会按响应体的字段名自动返回模拟数据。
调用 Mock
GET https://a1b2c3d4.mock.pstmn.io/api/users/1
x-api-key: <你的 Postman API Key>   # 私有 Mock 需要
2026 新能力：Cloud View 代码 Mock

除了基于 Example 的静态 Mock，现在还能用 JavaScript 写请求处理逻辑的代码级 Mock，在 Cloud View 里创建并部署为云端 Mock Server —— 每个 Mock 有独立 URL 且永久在线，可以做条件分支、动态计算、状态保持，比静态 Example 灵活得多。

16监控与性能测试

16.1 Monitor 定时监控

Monitor 是按计划定时运行集合的云端任务，用来持续观察线上 API 的健康状况与性能。

  • 创建：侧边栏 Monitors → Create Monitor，选集合与环境。
  • 频率：可设每小时 / 每天 / 每周，或 Cron 表达式；可选多地区运行。
  • 失败会发邮件或推送到 Slack 等集成。
  • 结果页能看到每次运行的通过率、响应时间趋势、失败原因。
监控用例写法

监控跑的是「只读」请求为主。别在监控里跑会写脏数据的接口；如果必须，用专门的测试账号并在请求里带上清理逻辑。

16.2 性能测试

Postman 支持用虚拟用户（VU）做负载测试：设定并发用户数与持续时间，观察吞吐量、P95 延迟、错误率。

2026 新能力：云端性能测试

现在可以把压测放到 Postman Cloud 跑：突破单机瓶颈、关掉电脑也继续跑、结果持久化可对比历史。还支持给压测配置 setup / teardown 集合（跑前造数据、跑后清数据）。云端压测按 VU 小时计费（Solo / Team 计划）。

17Postman Flows

Flows 是一个可视化的 API 工作流编排工具：把请求、数据处理、条件判断、延时、循环拖到画布上连起来，不用写代码就能搭出多步骤的自动化流程。

模块（Block）作用
Start流程入口，可设手动触发或定时
Send Request调用集合中的某个请求
Evaluate写一段 JS/FQL 处理数据
If / Else条件分支
For / Repeat / Delay循环、重复、延时
Output / Log输出结果、打印日志

典型场景：登录后取 token → 循环调列表接口翻页 → 聚合数据 → 生成报表 / 推送通知。Flows 已支持在 EU 数据驻留区域使用（Enterprise 计划）。

19接入 CI/CD

核心思路：把集合和环境导出（或用云端 UID），在流水线的测试阶段跑一遍，失败则阻断构建。

GitHub Actions

YAML · .github/workflows/api-test.yml
name: API Test
on: [push, pull_request]

jobs:
  newman:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install -g newman newman-reporter-htmlextra
      - name: Run Postman collection
        run: |
          newman run tests/collection.json \
            -e tests/env-ci.json \
            -r htmlextra,cli \
            --reporter-htmlextra-export report.html \
            --bail
      - name: Upload report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: api-test-report
          path: report.html

Groovy / YAML
# Jenkins Pipeline
stage('API Test') {

    sh 'newman run collection.json -e env.json -r junit --reporter-junit-export newman.xml'
  }

23常见问题排查

问题原因 / 解决办法
Could not get any response服务没启动 / 端口不对 / URL 写错 / 公司代理拦截。看 Console；Settings → Proxy 检查代理配置；本机服务用 127.0.0.1 而非 localhost 有时能绕过 IPv6 解析问题。
Web 端访问不了 localhostWeb 版无法直接访问本机。改用桌面端，或用 Postman CLI 的 postman tunnel 建立隧道，或在 Web 端装 Postman Desktop Agent。
变量显示红色（未解析）变量不在当前活动作用域 / 环境没选 / 改了没保存。悬停查看，点「Set variable」补上。
中文参数乱码确认请求头 Content-Type: application/json; charset=utf-8；URL 参数手动 EncodeURIComponent。
SSL 证书错误自签证书环境：Settings → General → 关闭 SSL certificate verification（仅测试环境）。
集合跑出来全是 401token 未传递：检查集合级 Authorization 是否 Inherit；Tests 里是否正确 pm.environment.set("token", ...)；环境是否选对。
setNextRequest 不生效请求名必须与集合里的名字完全一致（含空格和标点）；只在集合运行时生效。
Newman 跑过但 Postman 里结果不一致环境变量没随集合一起导出；数据文件路径不对；--bail 提前终止。用 -r cli 看详细日志。
响应时间忽快忽慢首次请求含 DNS/TLS 握手开销；网络抖动；服务端冷启动。用多次迭代取平均或看 P95。
JSON 解析失败 pm.response.json()响应不是合法 JSON（可能是 HTML 错误页）。先 console.log(pm.response.text()) 看原始内容。
