## 一、页面信息架构

```
工具箱 /toolbox
├── 页头（sticky）
│   ├── 顶部**仅保留一个返回按钮**（返回导航站；无其他顶部元素）
│   └── 标题「工具箱」+ 副标题（工具总数 / 当前筛选结果数）
├── 工具栏
│   ├── 搜索框（关键字，即时过滤，可清空）★ 在父容器内**水平居中**
│   └── 分类筛选（全部 / 各分类带数量 / **站内模块**专属分类；数量为 0 的分类自动隐藏）
├── 常用工具（收藏分组）★ 仅在有收藏时渲染
│   └── 卡片网格（同全部工具，复用 ToolboxCard）
├── 全部工具
│   └── 卡片网格（自适应列）
├── 最近使用（时间倒序，去重，上限 8）★ 仅在有记录时渲染
│   └── 紧凑卡片列表
├── 站内工具面板（点击站内自建工具时打开）
│   └── 本站自己实现的功能 UI（不跳转第三方）
└── 空状态 / 异常状态
    ├── 无搜索结果 → 友好提示 + 清空条件
    ├── 无收藏 → 引导空态
    └── 工具不可用 → 状态徽标 + 置灰不可点
```

信息层级：**先直达（常用/最近）→ 再检索（搜索/分类）→ 最后全量浏览**，符合工具聚合页的使用习惯。

**顶栏与主题约定**：工具箱页顶栏只保留「返回」一个操作，主题一律复用项目共用主题（`src/style.css` + `src/styles/dark.css`），
不为工具箱单独设置亮/暗主题，也不复制重复的主题变量。

## 二、路由与路径设计

沿用 `src/router/index.ts` 现有约定（懒加载 + `createWebHistory` + `scrollBehavior`）：

```ts
// src/router/index.ts（新增一项，其余不动）
const ToolboxView = () => import('../views/ToolboxView.vue')

routes: [
  // ...既有 home / workbench / business / student / teacher
  {
    path: '/toolbox',
    name: 'toolbox',
    component: ToolboxView
  }
]
```

| 项 | 取值 | 说明 |
|----|------|------|
| 路径 | `/toolbox` | 小写、与既有 `/workbench`、`/business` 同级 |
| 路由 name | `toolbox` | 供 `router.push({ name: 'toolbox' })` 使用 |
| 加载方式 | 路由级懒加载 | 不进导航站首屏包，满足首屏性能要求 |
| 滚动行为 | 复用全局 `scrollBehavior` | 前进/后退恢复原位置 |

### 3.1 「站内模块」专属分类

站内已有模块（`kind: 'module'`）单独成一个分类，与按业务领域划分的分类（开发/数据/媒体/效率）并列：

| 项 | 取值 |
|----|------|
| 分类 id | `site-module`（常量 `MODULE_CATEGORY_ID`，定义在 `src/toolbox/core/category.ts`） |
| 显示名 / 图标 | 站内模块 / 🧭，order 5（排在「其他」之前） |
| 归类方式 | **自动**：`registry.ts` 扫描后统一调用 `normalizeToolMeta()`，`kind === 'module'` 的工具强制归入该分类，元数据里不写 `category` 也不会漏配 |
| 页面表现 | 分类页签单独一项（`tb-cat-site-module`）；选中时分组副标题显示「· N 个模块，点击直达站内对应页面」；数量为 0 的分类（如当前为空的「效率工具」「其他」）自动隐藏，不占页签 |

> 这样新增一个站内模块工具时，只要声明 `kind: 'module'` 与站内 `url`，分类归属自动完成，无需同步改动分类配置。

### 3.2 Modal（工具弹框）v2 规范

尺寸与布局由工具元数据声明，面板壳统一实现，工具组件只管工作区：

```ts
interface ToolboxToolMeta {
  // ...v1 字段保留
  /** 弹框宽度档位：S 480 / M 720 / L 960 / XL 1120（默认 M，移动端一律全屏） */
  modalSize?: 'S' | 'M' | 'L' | 'XL'
  /** 工作区布局模板 T1–T6（默认 T1） */
  layout?: 'T1' | 'T2' | 'T3' | 'T4' | 'T5' | 'T6'
  /** 新增时间（用于「新」角标，YYYY-MM-DD） */
  addedAt?: string
}
```

`ToolboxToolPanel.vue` 统一提供：尺寸类映射（`.tb-modal--s/m/l/xl`）、Esc + 遮罩关闭、打开时 `body.tb-lock` 锁滚动、
**焦点陷阱**、`aria-modal`、关闭时若 `useToolDirty` 为「脏且未保存」则二次确认、`defineAsyncComponent` + `Suspense` +
`onErrorCaptured` 兜底、`prefers-reduced-motion` 禁用动画。布局模板由工具组件用 `tu-t1..tu-t6` 类声明（样式集中在 `tool-ui.css`）。

## 四、工具元数据字段定义

`src/config/toolbox.ts`：

```ts
/** 工具状态：决定卡片可否跳转 */
export type ToolboxToolStatus = 'active' | 'maintenance' | 'coming'

/** 工具元数据：新增工具只需追加一条 */
export interface ToolboxTool {
  /** 唯一 id（kebab-case），收藏/最近使用以此为键，改名不影响已收藏项 */
  id: string
  /** 名称（≤20 字，参与搜索） */
  name: string
  /** 图标：优先项目 Icon 组件 name，其次 emoji 兜底 */
  icon: string
  /** 一句话描述（参与搜索） */
  description: string
  /** 主分类 id（对应 TOOLBOX_CATEGORIES） */
  category: string
  /** 标签（参与搜索，可为空数组） */
  tags: string[]
  /** 状态：active 可打开；maintenance/coming 置灰不可点 */
  status: ToolboxToolStatus
  /** 工具形态：
   *  - 'internal' 站内自建工具：本站自己实现的功能，在站内工具面板打开（不跳第三方）
   *  - 'module'   站内已有模块：走站内路由跳转，url 为站内相对路径 */
  kind: 'internal' | 'module'
  /** 站内路由（仅 kind: 'module' 使用，如 /workbench、/business?section=stats）；
   *  站内自建工具不需要此字段 —— 严禁填写站外 URL */
  url?: string
  /** 同分类内排序，缺省按配置顺序 */
  order?: number
}

/** 分类元数据 */
export interface ToolboxCategory {
  id: string
  name: string
  icon: string
  order?: number
}
```

**字段与需求的对应**：名称 / 图标 / 描述 / 分类 / 标签 / 状态 / 工具形态（站内自建 or 站内模块）—— 全部覆盖需求文档 §4 的功能项。

## 五、搜索与筛选的实现思路

### 5.1 核心纯函数

```ts
/** 归一化：小写 + 去首尾空格 */
const norm = (s: string) => (s || '').toLowerCase().trim()

/** 把关键字拆成 token（支持空格多词，全部命中才算匹配） */
export function matchTokens(tool: ToolboxTool, q: string): boolean {
  const tokens = norm(q).split(/\s+/).filter(Boolean)
  if (!tokens.length) return true
  const hay = norm(`${tool.name} ${tool.description} ${(tool.tags || []).join(' ')}`)
  return tokens.every(t => hay.includes(t))
}

/** 过滤：分类 + 标签 + 关键字 叠加生效 */
export function filterToolboxTools(
  tools: ToolboxTool[],
  opts: { q?: string; category?: string; tag?: string } = {}
): ToolboxTool[] {
  const { q = '', category = '', tag = '' } = opts
  return tools
    .filter(t => !category || t.category === category)
    .filter(t => !tag || (t.tags || []).includes(tag))
    .filter(t => matchTokens(t, q))
    .sort((a, b) => (a.order ?? 999) - (b.order ?? 999))
}
```

### 5.2 交互与体验要点
- **即时**：监听 `input`，无需按钮；输入即过滤（`v-model` + `computed`）。
- **匹配范围**：名称 + 描述 + 标签，三者拼接后做包含匹配（覆盖需求「名称与描述的即时模糊匹配」，并额外支持标签）。
- **多词与与逻辑**：空格分词，全部命中才匹配，避免长词误命中。
- **高亮**：`highlight(text, tokens)` 返回分段数组，命中片段用 `<mark>` 包裹（样式沿用主色浅底）。
- **清空**：搜索框内 ✕ 一键清空；无结果时提供「清空条件」按钮（同时重置关键字与分类）。
- **数量反馈**：分类项与页头副标题实时显示结果数。

### 5.3 复杂度
工具量级为几十到几百，`filter` 为 O(n) 线性扫描，**无需索引或防抖**；若后续上千条再引入防抖与虚拟列表。

## 六、状态管理与本地持久化方案

### 6.1 状态划分

| 状态 | 存放位置 | 说明 |
|------|----------|------|
| 工具与分类配置 | `src/config/toolbox.ts`（静态） | 唯一数据源，运行时只读 |
| 关键字 / 当前分类 | `ToolboxView.vue` 内 `ref` | 页面级临时态，不持久化 |
| 收藏 | 本地持久化 | 跨会话保留 |
| 最近使用 | 本地持久化 | 跨会话保留 |

### 6.2 持久化选型：**localStorage**（最小改动）

- Key：`easy-web-tab:toolbox`
- 结构：
  ```ts
  interface ToolboxPrefs {
    favorites: string[]                 // 收藏的工具 id
    recent: Array<{ id: string; ts: number }>  // 最近使用，按 ts 倒序
  }
  ```
- 理由：数据量极小（几十个 id）、非关键数据、无需跨设备；用 localStorage 比接入 IndexedDB / settings 信封**改动最小**，且不触碰既有持久化链路。
- 读写封装在 `useToolboxPrefs.ts`：**读取时做 JSON 容错与字段校验**（脏数据回落默认值），**写入时 try/catch**，隐私模式下 localStorage 不可用时**降级为内存态**（功能可用，仅本次会话有效），符合需求「异常不阻断」。
- 最近使用：`recordRecent(list, id, now, limit = 8)` —— 去重（同 id 取最新）、截断、倒序。
- 后续如需云同步：把这份 prefs 并入既有 `settings` 信封即可，字段契约不变。

### 6.3 与 Pinia 的关系
本期**不新建 Pinia store**（状态简单且页面级），用 `useToolboxPrefs` 组合式函数即可，避免为小功能增加全局状态。若未来工具箱需要跨模块共享（如首页也展示常用工具），再提升为 `useToolboxStore`，接口保持不变。

## 七、如何以最小改动接入现有项目

### 7.1 改动清单（共 4 类，均为**新增或追加**，无既有逻辑重写）

| # | 文件 | 动作 | 说明 |
|---|------|------|------|
| 1 | `src/toolbox/**` | **新增目录** | 工具箱全部代码集中于此（types / core / prefs / config / components / views / styles） |
| 2 | `src/toolbox/tools/<id>/` | **新增目录** | **每个工具单独一个目录**：`index.ts`（元数据）+ 工具组件 |
| 3 | `src/router/index.ts` | **追加 2 行** | 懒加载 import + 一条 route |
| 4 | `src/views/HomeView.vue` | **追加 1 个按钮** | App Bar 左上角「🧰 工具箱」入口 |

**不改动**：现有模块（导航站/工作台/销售记账/学生/教师）、既有 store、路由其他项、样式体系、构建配置。

### 7.1.1 新增一个工具的标准步骤（零改动页面逻辑）

1. 建目录：`src/toolbox/tools/<tool-id>/`
2. 写元数据：`index.ts` 默认导出 `ToolboxToolEntry`
   ```ts
   import type { ToolboxToolEntry } from '../../types'

   const entry: ToolboxToolEntry = {
     meta: {
       id: 'my-tool', name: '我的工具', icon: '🛠',
       description: '一句话描述（参与搜索）',
       category: 'dev', tags: ['标签1'],
       status: 'active', kind: 'internal', order: 20
     },
     component: () => import('./MyToolTool.vue')
   }
   export default entry
   ```
3. 写实现：`MyToolTool.vue`（可直接复用 `tu-*` 通用类，无需写重复样式）
4. 完成 —— `registry.ts` 通过 `import.meta.glob` 自动发现，列表/搜索/筛选/收藏/最近使用全部生效。

> 复用站内已有页面时用 `kind: 'module'` + `url: '/xxx'`，无需组件目录（如 `tools/todo/`、`tools/ledger/`）。

### 7.2 入口按钮接入（左上角）

`HomeView.vue` 的 `app-bar-left` 区域（现为 `<WorkbenchManagePanel />`）追加：

- 后续可像「帮助/倒计时按钮」一样接入设置开关（可选，本期默认显示）。

### 7.3 样式与主题
- 组件用 `<style scoped>`，颜色/圆角/阴影/间距**全部引用 `src/style.css` 的 Design Token**（`--color-primary`、`--color-bg-card`、`--radius-lg`、`--shadow-card` 等），暗色模式由 `html.dark` 自动生效，**不写任何硬编码颜色**。
- 网格沿用项目 `.grid-auto` 思路或 scoped 内 `repeat(auto-fill, minmax(220px, 1fr))`，超小屏 `≤359px` 强制单列。
- 过渡沿用 `--motion-*` / `--transition-*` token，并自动继承全局 `prefers-reduced-motion` 处理。
- **顶栏**：工具箱页顶栏只保留「← 返回」按钮（`tb-back-btn`），复用 `.btn-help` / `.ghost-btn` 既有样式，不新增顶部控件。
- **搜索框居中**：搜索框在父容器内水平居中（`width:100%` + `max-width` + `margin-inline:auto`），
  窄屏自动铺满、宽屏居中且不过宽，无需额外媒体查询。
- **原型不自带主题**：`docs/工具箱原型.html` 直接 `<link>` 项目共用主题（`../src/style.css` + `../src/styles/dark.css`），
  不复制任何 Token，避免与项目主题重复或漂移。

### 7.4 国际化 / 类型 / 测试
- 项目**无 i18n**（无 vue-i18n / locales），文案直接写中文，与既有模块一致。
- 类型放 `src/types/index.ts` 或随 config 导出（建议随 config，避免污染全局类型文件）。
- 纯函数沿用 `node --experimental-strip-types` 直测方式（参照 `scripts/test-business-core.ts`），`scripts/test-toolbox-core.ts` 覆盖：
  过滤、多词搜索、状态不可用、最近使用去重截断、脏数据容错，**以及 20+ 个 core 模块的功能/边界/异常用例**（见 `npm run test:toolbox`）。

## 九、风险与后续演进

| 风险/待办 | 应对 |
|-----------|------|
| 工具数量增长后检索变慢 | 量级达千条时引入防抖 + 虚拟列表，core 接口不变 |
| 需要内嵌运行工具（iframe） | 元数据增加 `embed?: boolean` 与 `embedUrl`，卡片渲染切换，不影响现有字段 |
| 需要跨设备同步收藏 | 把 prefs 并入 settings 信封，字段契约不变 |
| 首页也想展示常用工具 | 抽出 `ToolboxFavBar.vue` 复用，或提升为 `useToolboxStore` |
| 图标依赖 Icon 组件可用名 | 元数据 `icon` 优先用 Icon name，未命中时 emoji 兜底（原型已采用 emoji） |
