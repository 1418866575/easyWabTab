## 一、页面信息架构

```
工具箱 /toolbox
├── 页头（sticky）
│   ├── 标题「工具箱」+ 副标题（工具总数 / 当前筛选结果数）
│   └── 返回/入口区（左上角「🧰 工具箱」入口按钮在导航站 App Bar，见 §7）
├── 工具栏
│   ├── 搜索框（关键字，即时过滤，可清空）
│   └── 分类筛选（全部 / 各分类，带数量）
├── 常用工具（收藏分组）★ 仅在有收藏时渲染
│   └── 卡片网格（同全部工具，复用 ToolboxCard）
├── 全部工具
│   └── 卡片网格（自适应列）
├── 最近使用（时间倒序，去重，上限 8）★ 仅在有记录时渲染
│   └── 紧凑卡片列表
└── 空状态 / 异常状态
    ├── 无搜索结果 → 友好提示 + 清空条件
    ├── 无收藏 → 引导空态
    └── 工具不可用 → 状态徽标 + 置灰不可点
```

信息层级：**先直达（常用/最近）→ 再检索（搜索/分类）→ 最后全量浏览**，符合工具聚合页的使用习惯。

目录：`src/components/toolbox/`

| `ToolboxView.vue` | 页面容器（路由组件） | 组装搜索/分类/分组；消费 core 纯函数得出展示数据；**不含业务判断** |

| `ToolboxSection.vue` | 分组容器（标题 + 网格 + 空态） | 复用于「常用」「全部」「最近」，统一空态插槽 |
| `ToolboxEmpty.vue` | 空/异常状态展示 | 按 `kind` 渲染不同文案与操作（no-result / no-fav / no-recent / empty） |

纯逻辑（零 Vue 依赖，可被 `node --experimental-strip-types` 直测，沿用 `businessCore` 约定）：

| 文件 | 职责 |
|------|------|
| `src/composables/toolboxCore.ts` | `filterToolboxTools` / `matchTokens` / `highlight` / `recordRecent` / `dedupeRecent` / 持久化数据的**纯读写解析** |
| `src/composables/useToolboxPrefs.ts` | 收藏与最近使用的**响应式封装**（读写 localStorage，异常降级） |
| `src/config/toolbox.ts` | 工具与分类的**静态配置**（唯一数据源） |

> 约定：组件**不做过滤/排序计算**，一律调用 `toolboxCore`；与项目「业务逻辑不进组件」的既有约定一致。

## 四、工具元数据字段定义

`src/config/toolbox.ts`：

```ts
/** 工具状态：决定卡片可否跳转 */
export type ToolboxToolStatus = 'active' | 'maintenance' | 'coming'

/** 工具元数据：新增工具只需追加一条 */
export interface ToolboxTool {
  /** 唯一 id（kebab-case），收藏/最近使用以此为键，改名不影响已收藏项 */
  id: string
  /** 名称（≤20 字，参与搜索） */
  name: string
  /** 图标：优先项目 Icon 组件 name，其次 emoji 兜底 */
  icon: string
  /** 一句话描述（参与搜索） */
  description: string
  /** 主分类 id（对应 TOOLBOX_CATEGORIES） */
  category: string
  /** 标签（参与搜索，可为空数组） */
  tags: string[]
  /** 状态：active 可跳转；maintenance/coming 置灰不可点 */
  status: ToolboxToolStatus
  /** 跳转地址：站内相对路径（如 /business?section=stats）或完整 URL */
  url: string
  /** 是否新标签打开，缺省 true */
  newTab?: boolean
  /** 同分类内排序，缺省按配置顺序 */
  order?: number
}

/** 分类元数据 */
export interface ToolboxCategory {
  id: string
  name: string
  icon: string
  order?: number
}
```

**字段与需求的对应**：名称 / 图标 / 描述 / 分类 / 标签 / 状态 / 跳转地址 —— 全部覆盖需求文档 §4 的功能项。

## 五、搜索与筛选的实现思路

### 5.1 核心纯函数

```ts
/** 归一化：小写 + 去首尾空格 */
const norm = (s: string) => (s || '').toLowerCase().trim()

/** 把关键字拆成 token（支持空格多词，全部命中才算匹配） */
export function matchTokens(tool: ToolboxTool, q: string): boolean {
  const tokens = norm(q).split(/\s+/).filter(Boolean)
  if (!tokens.length) return true
  const hay = norm(`${tool.name} ${tool.description} ${(tool.tags || []).join(' ')}`)
  return tokens.every(t => hay.includes(t))
}

/** 过滤：分类 + 标签 + 关键字 叠加生效 */
export function filterToolboxTools(
  tools: ToolboxTool[],
  opts: { q?: string; category?: string; tag?: string } = {}
): ToolboxTool[] {
  const { q = '', category = '', tag = '' } = opts
  return tools
    .filter(t => !category || t.category === category)
    .filter(t => !tag || (t.tags || []).includes(tag))
    .filter(t => matchTokens(t, q))
    .sort((a, b) => (a.order ?? 999) - (b.order ?? 999))
}
```

### 5.2 交互与体验要点
- **即时**：监听 `input`，无需按钮；输入即过滤（`v-model` + `computed`）。
- **匹配范围**：名称 + 描述 + 标签，三者拼接后做包含匹配（覆盖需求「名称与描述的即时模糊匹配」，并额外支持标签）。
- **多词与与逻辑**：空格分词，全部命中才匹配，避免长词误命中。
- **高亮**：`highlight(text, tokens)` 返回分段数组，命中片段用 `<mark>` 包裹（样式沿用主色浅底）。
- **清空**：搜索框内 ✕ 一键清空；无结果时提供「清空条件」按钮（同时重置关键字与分类）。
- **数量反馈**：分类项与页头副标题实时显示结果数。

### 5.3 复杂度
工具量级为几十到几百，`filter` 为 O(n) 线性扫描，**无需索引或防抖**；若后续上千条再引入防抖与虚拟列表。

## 六、状态管理与本地持久化方案

### 6.1 状态划分

| 状态 | 存放位置 | 说明 |
|------|----------|------|
| 工具与分类配置 | `src/config/toolbox.ts`（静态） | 唯一数据源，运行时只读 |
| 关键字 / 当前分类 | `ToolboxView.vue` 内 `ref` | 页面级临时态，不持久化 |
| 收藏 | 本地持久化 | 跨会话保留 |
| 最近使用 | 本地持久化 | 跨会话保留 |

### 6.2 持久化选型：**localStorage**（最小改动）

- Key：`easy-web-tab:toolbox`
- 结构：
  ```ts
  interface ToolboxPrefs {
    favorites: string[]                 // 收藏的工具 id
    recent: Array<{ id: string; ts: number }>  // 最近使用，按 ts 倒序
  }
  ```
- 理由：数据量极小（几十个 id）、非关键数据、无需跨设备；用 localStorage 比接入 IndexedDB / settings 信封**改动最小**，且不触碰既有持久化链路。
- 读写封装在 `useToolboxPrefs.ts`：**读取时做 JSON 容错与字段校验**（脏数据回落默认值），**写入时 try/catch**，隐私模式下 localStorage 不可用时**降级为内存态**（功能可用，仅本次会话有效），符合需求「异常不阻断」。
- 最近使用：`recordRecent(list, id, now, limit = 8)` —— 去重（同 id 取最新）、截断、倒序。
- 后续如需云同步：把这份 prefs 并入既有 `settings` 信封即可，字段契约不变。

### 6.3 与 Pinia 的关系
本期**不新建 Pinia store**（状态简单且页面级），用 `useToolboxPrefs` 组合式函数即可，避免为小功能增加全局状态。若未来工具箱需要跨模块共享（如首页也展示常用工具），再提升为 `useToolboxStore`，接口保持不变。

### 7.3 样式与主题
- 组件用 `<style scoped>`，颜色/圆角/阴影/间距**全部引用 `src/style.css` 的 Design Token**（`--color-primary`、`--color-bg-card`、`--radius-lg`、`--shadow-card` 等），暗色模式由 `html.dark` 自动生效，**不写任何硬编码颜色**。
- 网格沿用项目 `.grid-auto` 思路或 scoped 内 `repeat(auto-fill, minmax(220px, 1fr))`，超小屏 `≤359px` 强制单列。
- 过渡沿用 `--motion-*` / `--transition-*` token，并自动继承全局 `prefers-reduced-motion` 处理。

### 7.4 国际化 / 类型 / 测试
- 项目**无 i18n**（无 vue-i18n / locales），文案直接写中文，与既有模块一致。
- 类型放 `src/types/index.ts` 或随 config 导出（建议随 config，避免污染全局类型文件）。
- 纯函数沿用 `node --experimental-strip-types` 直测方式（参照 `scripts/test-business-core.ts`），新增 `scripts/test-toolbox-core.ts` 覆盖：过滤、多词搜索、状态不可用、最近使用去重截断、脏数据容错。

## 九、风险与后续演进

| 风险/待办 | 应对 |
|-----------|------|
| 工具数量增长后检索变慢 | 量级达千条时引入防抖 + 虚拟列表，core 接口不变 |
| 需要内嵌运行工具（iframe） | 元数据增加 `embed?: boolean` 与 `embedUrl`，卡片渲染切换，不影响现有字段 |
| 需要跨设备同步收藏 | 把 prefs 并入 settings 信封，字段契约不变 |
| 首页也想展示常用工具 | 抽出 `ToolboxFavBar.vue` 复用，或提升为 `useToolboxStore` |
| 图标依赖 Icon 组件可用名 | 元数据 `icon` 优先用 Icon name，未命中时 emoji 兜底（原型已采用 emoji） |
