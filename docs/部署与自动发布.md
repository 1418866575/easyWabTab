# 部署与自动发布（webTab.sh）

`webTab.sh` 是 easy-web-tab 的一键部署脚本：拉取代码 → 判断更新 → 编译 → 备份 → 发布到 nginx。

## 一、基本用法

```bash
# 手动执行
chmod +x webTab.sh
./webTab.sh
```

首次执行会clone 仓库并编译，耗时较长；之后每次执行若**远端无更新**会秒级返回。

## 二、定时执行（每 2 小时）

### 推荐做法

```bash
crontab -e
```

加入以下内容（每 2 小时的第 0 分钟执行）：

```cron
0 */2 * * * /root/workspace/easy-web-tab/webTab.sh >> /var/log/easy-web-tab-deploy.log 2>&1
```

`0 */2 * * *` 的触发时刻：

```
00:00  02:00  04:00  06:00  08:00  10:00
12:00  14:00  16:00  18:00  20:00  22:00
```

即每天 12 次。

### 避开整点高峰

若不想与其他定时任务撞在同一时刻，把分钟数改成任意非零值（如 17）：

```cron
17 */2 * * * /root/workspace/easy-web-tab/webTab.sh >> /var/log/easy-web-tab-deploy.log 2>&1
```

触发时刻变为 `00:17、02:17、04:17 … 22:17`。

### 注意事项

| 项 | 说明 |
|---|---|
| **必须用绝对路径** | cron 的 `PATH` 很短，不能用相对路径，也不能依赖 `~/.bashrc` 里的别名/函数 |
| **脚本需可执行** | `chmod +x /root/workspace/easy-web-tab/webTab.sh`，否则 cron 里会报 permission denied |
| **日志建议重定向到文件** | 否则 cron 会尝试给本地用户发邮件，多数服务器上会丢失 |
| **脚本是幂等的** | 无更新时直接 `exit 0`，重复执行不会有副作用 |

### 查看是否生效

```bash
# 确认定时任务已写入
crontab -l

# 观察执行日志
tail -f /var/log/easy-web-tab-deploy.log
```

## 三、并发防护（建议）

若单次编译耗时可能超过 2 小时，下一轮定时任务会与本轮重叠，两个进程同时写 `dist` / nginx 目录会互相干扰。任选一种防护：

### 方案 A：crontab 层加锁（推荐，最简单）

```cron
0 */2 * * * flock -n /var/lock/easy-web-tab-deploy.lock /root/workspace/easy-web-tab/webTab.sh >> /var/log/easy-web-tab-deploy.log 2>&1
```

`-n` 表示非阻塞抢锁：抢不到就直接放弃本轮（`flock` 返回 1，不产生任何副作用）。

### 方案 B：脚本内自锁

在 `webTab.sh` 顶部 `set -euo pipefail` 之后加两行：

```bash
exec 9>/var/lock/easy-web-tab-deploy.lock
flock -n 9 || { echo "[$(ts)] 已有部署任务在运行，本轮跳过"; exit 0; }
```

## 四、执行流程

| 步骤 | 行为 | 无更新时 |
|---|---|---|
| 1. 准备代码 | 首次 `git clone`；之后 `git fetch` + `merge --ff-only`（**不删工作目录**） | 仍会执行（需 fetch 才能判断） |
| 2. 更新判定 | 比对本地 HEAD 与 `origin/master` | **直接 exit 0，不编译不发布** |
| 3. 准备依赖 | `node_modules` 已存在则跳过拷贝；否则从共享目录拷 / `npm install` | 不执行 |
| 4. 编译 | `npm run build`，产物为空即中止 | 不执行 |
| 5. 备份 | 线上版本打包进备份目录，保留最近 10 份 | 不执行 |
| 6. 发布 | 清空 nginx 目录后拷入新产物 | 不执行 |

## 五、关键设计

- **不删除工作目录**：改为增量拉取。拉取失败时旧代码与线上站点都完好，不会因一次网络异常把工作目录搞没。
- **有更新才发布**：无更新且本地已有产物时直接退出，避免每次白跑构建、也避免无谓覆盖线上。
- **依赖复用**：`node_modules` 已存在就不拷贝，省一次GB 级复制；共享依赖目录也没有时退化为 `npm install`（原脚本会直接失败）。
- **失败即中止**：`set -euo pipefail`，所有关键步骤失败都明确输出「线上版本未改动」，不会带着失败/旧产物继续部署。
- **脏工作区检测**：拉取前检查未提交改动并明确提示，否则 `--ff-only` 失败会表现成莫名的构建错误。
- **发布前后校验**：编译产物为空、发布后目录为空，都判定异常并中止。

## 六、排错速查

| 日志关键字 | 含义与处理 |
|---|---|
| `无更新` | **正常**。远端没变化，线上仍是上一版本 |
| `工作目录存在未提交改动` | 服务器上有人改过文件或有构建残留。确认无用后可清理：<br>`cd /root/workspace/easy-web-tab && git checkout -- . && git clean -fd` |
| `git fetch 失败` | 网络异常或凭据问题。线上版本未改动，可稍后重试 |
| `编译失败` | 线上仍为上一版本，查看构建输出定位问题 |
| `发布后目录为空` | 拷贝异常，检查 nginx 目录权限 |

查看历史发布记录：

```bash
ls -lt /root/workspace/easy-web-tab-backups/
```

## 七、相关路径

| 用途 | 路径 |
|---|---|
| 工作目录（代码） | `/root/workspace/easy-web-tab` |
| 共享依赖来源 | `/root/workspace/node_modules` |
| nginx 站点目录 | `/usr/share/nginx/html` |
| 备份目录 | `/root/workspace/easy-web-tab-backups` |

> 上述路径在脚本头部以变量集中定义（`WORK_DIR` / `SHARED_NODE_MODULES` / `NGINX_HTML` / `BACKUP_DIR`），可按实际环境修改。
