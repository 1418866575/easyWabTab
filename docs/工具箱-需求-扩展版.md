## 0. 文档说明

### 0.1 目的

将 A、B 两个在线工具站的工具集合做归并分析，产出**可直接进入开发的需求文档**：工具清单、实现逻辑、属性定义、布局结构四要素齐备，并明确「**不跳转、统一弹框承载**」的形态约束。

### 0.2 与 v1 的关系

| 项 | v1（已落地） | v2（本文档） |
|---|---|---|
| 工具数 | 16（8 站内自建 + 6 站内模块 + 2 占位） | 在 v1 基础上扩展到 **37 个工具条目**（其中 8 个为已实现工具的升级项） |
| 分类 | dev / data / media / effi / other + site-module | 重构为 **9 个业务分类** + site-module（见 §3） |
| 打开方式 | 站内自建走弹框、站内模块走路由 | **统一弹框（Modal）**，路由仅保留 `/toolbox` 一个入口 |
| 本文档定位 | 基线 | 增量需求；v1 已实现部分按 §6 升级，不推翻重写 |

### 0.3 术语

- **Modal（工具弹框）**：卡片点击后在**当前页面**之上打开的工具容器，不产生路由跳转、不打开新窗口。
- **工作区 / 结果区**：Modal 内的输入区与输出区，按 §5.3 的布局模板组织。
- **纯前端**：全部计算在浏览器完成，不上传任何数据（延续项目"本地处理"约定）。
- **尺寸档**：Modal 宽度档位 S(480) / M(720) / L(960) / XL(1120)，移动端一律全屏。

### 0.4 硬性约束（贯穿全文）

1. **禁止跳转**：点击工具卡片只打开 Modal，不得 `router.push` 到工具页、不得 `window.open`、不得 iframe 嵌入外部站点。（唯一例外：`kind: 'module'` 的站内模块仍走站内路由，见 v1。）
2. **数据不出端**：所有工具纯前端实现；涉及图片/文件的一律 `FileReader` + `canvas` 本地处理。
3. **零冗余主题**：样式统一取 `src/style.css` 与 `src/styles/dark.css` 的 Design Token，工具 UI 复用 `src/toolbox/styles/tool-ui.css`（`tu-` 前缀）。
4. **目录约定不变**：每个工具一个目录 `src/toolbox/tools/<id>/`（`index.ts` 元数据 + 组件），`registry.ts` 自动扫描注册。
5. **依赖从简**：优先零依赖或使用项目已有依赖（`crypto-js` / `markdown-it` / `js-yaml` / `xlsx` / `echarts`）；新增 npm 依赖需在需求中显式列出并说明理由（见 §7.3）。

## 1. 对标站分析结论

### 1.1 A 站（toolsite.cn）概览

- 工具数：**10 个**（首页即全集，无分页）。
- 导航方式：**标签筛选**（25 个标签 chip 横排，如 图片处理 / 开发工具 / 数据处理 / JSON工具 / 文本处理 / 颜色处理 / 安全工具…），**无搜索框**。

## 4. 工具详细需求

> 每个工具统一给出：**定义 / 实现逻辑（输入→处理→输出）/ 属性定义（输入·选项·输出·校验）/ 弹框形态 / 依赖与限制 / 验收要点**。
> 弹框形态中的**布局模板**代号见 §5.3：T1 单栏输入→结果、T2 左右双栏、T3 上下双栏、T4 表单→结果卡片、T5 画布工作台、T6 列表/表格工作台。

### 4.1 开发工具（dev）

#### #1 JSON 格式化（美化 / 压缩 / 校验） 🔁AB重复 · 升级 · P0

- **定义**：JSON 字符串的语法校验、格式化美化、压缩、键排序与树形浏览。
- **实现逻辑**：
  1. 读取输入文本 → `JSON.parse` 解析；
  2. 解析失败 → 从 `SyntaxError.message` 提取位置（正则匹配 `position (\d+)`）→ 换算**行号/列号** → 在结果区报错并高亮输入区对应行；
  3. 解析成功 → 按需递归排序键名 → `JSON.stringify(obj, null, indent)` 输出（压缩模式用 `JSON.stringify(obj)`）；
  4. 语法高亮：对输出文本做**分词片段化**（键/字符串/数字/布尔/标点），模板渲染 `<span class>` + `<mark>`，**禁止 `v-html`**；
  5. 树形视图：递归对象生成节点树（路径 = JSON Path），支持折叠展开。
- **属性定义**：
  - 输入：`text`（多行文本，必填，支持粘贴/拖入 .json 文件）
  - 选项：`indent`（2空格｜4空格｜Tab，默认 2）、`sortKeys`（布尔，默认关）、`mode`（美化｜压缩，默认美化）、`view`（代码｜树形，默认代码）
  - 输出：格式化文本（可复制、可下载 `.json`）、错误对象 `{ line, column, message }`、树形节点数组
  - 校验：非空；大小上限 **2 MB**（超出提示分块处理）；嵌套深度上限 **100**（防栈溢出）；重复键以最后一次为准（与 `JSON.parse` 一致，提示用户）
- **弹框形态**：L(960) · T2 左右双栏（左输入 / 右结果，结果区顶部切换 代码/树形）
- **依赖**：零依赖
- **验收**：错误定位行号列号准确；10 万字符输入 1s 内出结果；树形视图可折叠；压缩模式输出单行

#### #2 JSON / YAML / TOML 互转 · 新建 · P0

- **定义**：三种配置格式的互相转换，含语法校验。
- **实现逻辑**：源格式解析为 JS 对象 → 校验 → 序列化为目标格式；源格式支持"自动检测"（JSON 以 `{`/`[` 起始；YAML 含 `key: value`；TOML 含 `[section]` / `key = value`）→ 三方向转换 `JSON↔YAML`、`JSON↔TOML`（YAML↔TOML 经 JSON 中转）。
- **属性定义**：
  - 输入：`source`（多行文本，必填）、`from`（auto｜json｜yaml｜toml，默认 auto）、`to`（json｜yaml｜toml，默认 yaml）
  - 选项：`indent`（2/4）、`preserveComments`（布尔，默认关，YAML 注释保留尽力而为）
  - 输出：目标格式文本（可复制/下载，扩展名随目标格式）
  - 校验：解析失败时展示源格式的行号与原因；TOML 不支持的嵌套结构（表数组）需在转换前提示"可能失真"
- **弹框形态**：L(960) · T2（左源文本+格式选择，右结果）
- **依赖**：`js-yaml`（**项目已有**）；TOML 解析需新增 `@iarna/toml`（约 30KB）或自实现子集（见 §7.3）
- **验收**：三种格式 6 个方向互转正确；错误有行号；大文件（1MB）不卡死

#### #3 JSON 转 XML / Excel · 新建 · P1

- **定义**：JSON 数组/对象导出为 XML 或 Excel（.xlsx）。
- **实现逻辑**：JSON.parse → 若是数组，取第一层元素生成表头（键并集）→ `xlsx` 的 `json_to_sheet` 生成工作表 → `writeFile` 下载；XML 方向：递归生成节点（数组元素用 `<item>` 包裹，属性/文本节点按值类型判定），根元素可配置。
- **属性定义**：
  - 输入：`text`（JSON 文本，必填）、`rootName`（XML 根元素名，默认 `root`）
  - 选项：`target`（xml｜xlsx）、`arrayItemName`（默认 `item`）、`prettyXml`（布尔，默认开）

#### #33 密码生成器 🔁AB重复 · 新建 · P0

- **定义**：本地生成可配置强度的随机密码。

- **依赖**：零依赖

### 5.1 打开与关闭

| 项 | 规则 |
|---|---|

| 层级 | `z-index: var(--z-modal)`；遮罩 `rgba(0,0,0,.5)` + 淡入 |

### 5.4 统一区块

```
┌──────────────────────────────────────────────┐
│ 头部：图标 + 工具名 + 一句话描述        [?][✕] │
├──────────────────────────────────────────────┤
│ 工具条：[示例] [执行] [清空]  选项：…          │  ← 选项即地（inline），不另开设置
├──────────────────────────────────────────────┤
│ 工作区（按 T1–T6 排版）                       │
│   · 输入区：label + 控件 + 字数/大小统计       │
│   · 结果区：结果 + 空态「等待输入」            │
│   · 错误条：图标 + 文案 + 定位（行/列/字段）   │
├──────────────────────────────────────────────┤
│ 底部：[复制] [下载] [重置]        统计/耗时    │
│ 折叠：使用说明（核心功能 / 步骤 1-2-3）        │
└──────────────────────────────────────────────┘
```

- **即时计算 vs 按钮执行**：纯文本转换类（Base64/Hash/进制/颜色）**即时计算**（防抖 120ms）；重计算类（图片、Excel、Mermaid、正则全局匹配）用**显式按钮**（`执行`），并显示耗时。
- **复制**：`navigator.clipboard.writeText`，失败回落到隐藏 textarea；复制后 toast 提示。
- **下载**：`Blob` + `URL.createObjectURL` + `<a download>`，用完 `revokeObjectURL`。
- **示例数据**：每个工具必须提供 `示例` 按钮（一键填充可运行的样例输入）。

## 8. 验收标准

1. **形态**：全部工具点击后打开 Modal，页面 URL 不变、无新窗口、无 iframe、无第三方域名请求（Network 面板可验）。
2. **数据**：图片/文件类工具全程本地处理，无任何上传请求。
3. **性能**：工具组件各自独立 chunk（构建产物可验）；主包不因新增工具增大；单工具首屏打开 ≤300ms（本地）。
4. **一致性**：全部使用 Design Token，暗色模式下无对比度问题；移动端全屏 Modal 可用。
5. **可测**：每个工具至少 3 条纯函数用例（输入→输出、边界、异常），`npm run test:toolbox` 全绿。
6. **可用性**：每个工具有示例数据、错误提示可定位、结果可复制/下载；关闭有内容时二次确认。
7. **无障碍**：Modal 焦点管理、`aria-modal`、按钮 44px 触控目标、`prefers-reduced-motion` 生效。
