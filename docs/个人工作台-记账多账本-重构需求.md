# 个人工作台 · 记账管理多账本重构 — 需求文档

> 状态：待评审（仅需求，未实现）
> 关联分支：`20261001-teacher-opt-sifujiang`（合并 master 后）
> 目标：将当前「单账本」记账重构为「按自然年 + 同一年可多本」的多账本架构，数据相互隔离、统计准确，并在右上角设置弹框新增「记账管理」设置。

---

## 0. 调研结论摘要

- 个人记账当前是**单账本扁平结构**：`src/stores/workbenchLedger.ts` 用 `categories`/`entries` 两个 `ref` 直接读写 IDB store `'ledger'`（单条记录 `{categories, entries}`），无「账本 / 年份 / 多实例」概念。
- 计算层 `src/composables/ledgerCore.ts` 的所有统计函数（月度统计、存款累计、趋势、近 7 日、占比等）均以**扁平 `entries[]` / `categories[]`** 为入参，内部按 `monthKeyOf(e.date)` 过滤——天然适合「传入当前账本的数据」即可零改动复用。
- **项目内已有成熟的多账本范本**：销售记账（`business` 模块）已落地 `BusinessStoreData { ledgers, currentLedgerId }` + `BusinessLedger{id,year,seq,name,data,createdAt,updatedAt}`，并采用「`categories`/`entries` 等对外仍是可写 computed，实际指向当前账本 data」的模式，使业务面板**无需感知账本**。本重构应**镜像该模式**，复用其 `ledgerCodeOf` / `ledgerDefaultName` / `nextLedgerSeq` / `sortedLedgers` 思路，降低风险。

---

## 1. 背景与目标

**背景**：当前个人记账把所有年份、所有场景（日常开销、旅行、装修、某项目专项等）混在一个账本里，无法按「年」或「用途」分账，年底/换场景时记录与统计纠缠，导出/清理困难。

**目标**：

1. 每个账本**记录一个自然年**的数据。
2. **同一年中允许创建并管理多个账本**（例如「2026 日常」「2026 装修」）。
3. 账本之间**数据相互隔离**：切换账本后，列表、统计、图表、导出全部只反映当前账本。
4. 提供**创建 / 列表展示 / 切换 / 按年度归属管理**能力。
5. 在右上角设置弹框新增「记账管理」设置：创建账本、删除账本、清除账本数据、删除整个账本。
6. 保证查询与统计准确（不串账本、不串年份）。

## 2. 现状剖析（单账本）

| 层 | 位置 | 当前形态 |
|----|------|---------|
| 类型 | `src/types/index.ts` | `LedgerData { categories, entries }`、`LedgerCategory{id,name,type,isBuiltIn}`、`LedgerEntry{id,date,categoryId,amount,note?,createdAt,updatedAt}`、`DEFAULT_LEDGER_CATEGORIES`（8 内置） |
| 存储 | `src/stores/workbenchLedger.ts` | IDB store `'ledger'` 单条记录 `{categories, entries}`；`loadLedger()` 读经 `normalizeLedgerData`，`saveLedger()` 用 `idbPut('ledger', {...}) + markDirty()` |
| 计算 | `src/composables/ledgerCore.ts` | 纯函数：`normalizeLedgerData/normalizeLedgerEntry/emptyLedgerData`（用 8 内置）、`calcMonthlyStats`、`calcDepositTotal`、`calcTrendSeries`、`calcDailyExpenseSeries`、`trendChartScale`、`dailyExpenseChartScale`、`monthKeyOf`、`planAutoCopy` 等 |
| UI | `src/components/workbench/WorkbenchLedger.vue` | 月份条 + 6 张统计卡 + 图表区 + 记录列表/弹框；全部直接读 `store.entries` / `store.categories` |
| 设置 | `src/components/AppSettingsDialog.vue` | `wb` 主 tab 下已有 `wb-ledger-cat`（记账**分类**管理），无账本级管理入口 |

**现状关键点**：`WorkbenchLedger.vue` 与 `ledgerCore` 只通过 `store.entries` / `store.categories` 这两个访问点取数。只要让这两个访问点在 store 内部「指向当前账本」，UI 与计算层**几乎零改动**——这是降低风险的核心抓手（business 模块正是靠这一点让面板零改）。

## 3. 目标架构（镜像 business 已验证模式）

### 3.1 核心思想
在 store 内部引入「账本容器」，但对外**维持** `categories` / `entries`（以及 `incomeCategories` / `expenseCategories` / 各分类 computed）等既有 getter/action 不变，把它们改为「指向当前账本 data」的**可写 computed**。这样：
- `WorkbenchLedger.vue` 不用改取数方式；
- `ledgerCore` 所有统计函数不用改（仍收 `entries/categories`）；
- 仅 store 内部 + 新增账本管理逻辑需要动。

### 3.2 账本数据结构（新增类型，置于 `src/types/index.ts`）

```ts
/** 个人记账单账本（按自然年，同年可多本） */
export interface PersonalLedger {
  id: string
  year: number          // 自然年（账本归属年，写入记录年份必须等于它）
  seq: number           // 同一年内序号（从 1 起，唯一），编号 = YYYY-NN
  name: string          // 用户可见名，如「2026年账本」「2026年账本（02）」「2026 装修」
  data: LedgerData      // 该账本全部数据：{ categories, entries }
  createdAt: string
  updatedAt: string
}

/** 个人记账多账本容器（IDB store 'ledger' 的存储结构） */
export interface LedgerStoreData {
  schemaVer: number
  ledgers: PersonalLedger[]
  currentLedgerId: string
}
```

> `LedgerData` 不变（仍是 `{ categories, entries }`），只是从「全局唯一」变为「每账本一份」。每个新账本创建时由 `emptyLedgerData()` 播种 8 个内置分类（与现状一致）。

### 3.3 存储结构（IDB store `'ledger'` 信封升级）
- 旧：`{ categories, entries }`（单条扁平）。
- 新：`LedgerStoreData { schemaVer, ledgers: PersonalLedger[], currentLedgerId }`。
- **迁移**：`loadLedger()` 检测旧结构（无 `ledgers` 数组）→ 用 `normalizeLedgerStore` 把旧 `{categories, entries}` 整体包成「当前年账本」（seq=1，code=`YYYY-01`），立即落库，保证备份/云同步/其它标签页读到新结构。business 模块的 `normalizeBusinessStore` 就是这么做的，可直接借鉴写法。

### 3.4 区分维度（账本如何彼此区分）
| 维度 | 说明 | 是否可变 |
|------|------|---------|
| `year` | 自然年，账本归属年 | 创建后不变 |
| `seq` | 同一年内序号 | 创建后不变 |
| `code`（`YYYY-NN`） | 由 year+seq 派生的可读编号，唯一 | 派生，不变 |
| `name` | 用户命名（可重复，但建议唯一） | 可改（重命名） |
| `id` | 内部主键 | 不变 |

- **数据隔离边界**：一切记账记录（entries）与分类（categories）都挂在所属 `PersonalLedger.data` 下；切换账本即整体切换数据集，绝不在账本间共享 entry/category。
- **年度归属**：每本账本只记录其 `year` 对应的数据；写入 entry 时校验 `entry.date` 的年份 === 账本 `year`，跨年拒绝（提示切到对应年份账本），与 business 的 `checkLedgerYearWrite` 守卫一致。

## 4. 账本管理（右上角设置弹框「记账管理」）

### 4.1 入口
- 在 `AppSettingsDialog.vue` 的 `wb` 主 tab 下**新增子 tab `wb-ledger`（记账管理）**，并加到左侧 rail 的「个人工作台」分组。
- 需改 4 处（与现有效果门控一致）：
  1. `type WbSubTab` 联合类型加 `'wb-ledger'`；
  2. `SUB_TABS.wb` 加 `{ key: 'wb-ledger', label: '记账管理' }`；
  3. `NAV_GROUPS` 的 `wb` 分组 `items` 加 `{ key: 'wb-ledger', label: '记账管理', icon: 'ledger', tab: 'wb', sub: 'wb-ledger' }`；
  4. 内容区加 `<div v-if="activeTab==='wb' && activeSubTab==='wb-ledger'">`。
- 既有 `wb-ledger-cat`（分类管理）保留，二者职责分离：**分类管理 = 当前账本内的分组**；**记账管理 = 账本级别的创建/切换/清理/删除**。

### 4.2 创建账本
- 表单：年份（默认当前年，下拉/数字）、名称（可选，留空用默认名 `YYYY年账本` / 第 2 本起 `YYYY年账本（02）`）。
- 编号预览：创建前即显示即将生成的 `YYYY-NN`（复用 `nextLedgerSeq` 思路）。
- 规则：同年份序号自动分配；创建成功后**自动切换为当前账本**；新账本播种 8 内置分类、空流水。
- 校验：年份非法（如 <1970 或 >9999）提示；名称空则用默认名。

### 4.3 列表展示
- 账本列表（年份倒序 + 同年序号升序，复用 `sortedLedgers` 思路）：每行显示 `code` + 名称 + 记录数（entries.length）+ 是否为「当前」。
- 行内可**重命名**（仅改 name，编号/年份不变）。

### 4.4 切换账本
- 设置页提供切换入口；同时**在 `WorkbenchLedger.vue` 头部新增账本切换器**（镜像 `BusinessLedgerSwitcher.vue`，读取个人 store），展示当前 `code + 名称`，下拉列出所有账本，点击切换。
- 切换后 `currentLedgerId` 持久化；列表/统计/图表/导出自动随当前账本刷新（computed 驱动）。

### 4.5 清除账本数据
- 含义：**清空该账本下的所有记账记录（entries）**，但**保留账本本体与分类（categories）**——相当于「重置流水」。
- 二次确认弹框，提示将删除 N 条记录、分类保留。
- 不受「当前/最后一本」限制（账本本体仍在）。

### 4.6 删除整个账本
- 含义：**连同账本本体、分类、所有记录一起移除**（账本从列表消失）。
- 守卫（与 business `ledgerDeleteGuard` 一致）：
  - `is-current`：当前正在使用的账本禁止删（需先切换到其他账本）；
  - `last-one`：至少要保留一个账本，最后一个不可删；
  - `not-found`：账本不存在。
- 删除后 `currentLedgerId` 回落到默认账本（当前年 → 年份最大）。
- 二次确认（危险操作，明确不可恢复，建议先导出备份）。

### 4.7 复用现有实现
- `AppSettingsDialog.vue` 中 business 的「账本管理」区块（约 1271–1393 行）是现成范本：创建表单 + 列表 + 重命名 + 清空 + 删除 + 守卫 + 提示文案。直接镜像，把 `businessStore` 换成个人 `ledStore`，账本类型换 `PersonalLedger`，core 函数换成 ledger 侧对应实现。

## 5. 统计/查询准确性（数据隔离）

- `WorkbenchLedger.vue` 的所有 computed（`monthStats`、`depositTotal`、`trendSeries`、`donutSegments`、`dailySeries`、`monthEntries`、`viewEntries`）继续读 `store.entries` / `store.categories`——重构后这两个访问点指向**当前账本**，统计自然只反映当前账本，**无需改计算逻辑**。
- 月度统计 `calcMonthlyStats` 按 `monthKeyOf(e.date)` 过滤，因 entry 年份已被年守卫锁为账本年份，跨账本串数据不可能发生。
- 导出 CSV（`exportLedgerCsv`）仅导当前账本选中月记录，符合预期。
- 全量导出/导入（`handleWbExport/Import`，走 `idbExportAll`）序列化整个 `ledger` 信封（含多账本），导入时经 `normalizeLedgerStore` 还原，**无需改导出逻辑**（仅导入成功提示里的「记账 N 笔」改为当前账本笔数，或改为「账本 M 本」）。

## 6. 年归属守卫

- store 内部 `guardLedgerYear(date): { ok, reason?, message? }`，写入 entry 前校验 `new Date(date).getFullYear() === currentLedger.year`。
- 跨年写入：UI 提示「该账本仅记录 YYYY 年数据，请切换到对应年份账本」，并给出「去切换/去创建」快捷操作（参考 business 引导条）。
- 既有 `applyMonthlyAutoCopy`（工资/房贷月度自动复制）在重构后作用于当前账本 data，逻辑不变。

---

## 7. 云同步 / 备份兼容

- 个人记账数据经 `idbPut('ledger', ...)` + `markDirty()` 触发，落在 **workbench 信封**（v10 拆分的 `workbench.json`）。多账本只是该信封内结构变大，**信封协议不变**，云同步零改动。
- 备份导出（`idbExportAll`）与快照（`snapshots`）原本就整包序列化 `'ledger'`，多账本后继续可用。
- 旧备份（单账本）导入：`normalizeLedgerStore` 兼容旧扁平结构，自动迁入「当前年账本」，历史数据不丢。

## 8. 实现步骤拆解（建议）

1. **类型层**：`src/types/index.ts` 加 `PersonalLedger` / `LedgerStoreData`；`ledgerCore` 加 `normalizeLedgerStore` / `normalizePersonalLedger`（对齐 businessCore 的 `normalizeBusinessStore` / `normalizeLedger`）。
2. **core 函数**：在 `ledgerCore.ts` 新增个人账本纯函数（镜像 businessCore 同名思路，输入输出替换为 `PersonalLedger`/`LedgerData`）：
   - `ledgerDefaultName(year, seq)`、`ledgerCodeOf`、`nextLedgerSeq`、`sortedLedgers`
   - `createPersonalLedger(list, year, name?)`、`renamePersonalLedger`、`clearPersonalLedgerRecords`、`deletePersonalLedger`、`personalLedgerDeleteGuard`、`checkPersonalLedgerYearWrite`
3. **store 重构** `src/stores/workbenchLedger.ts`：
   - 内部 `ledgers: ref<PersonalLedger[]>` + `currentLedgerId`，`currentLedger` computed；
   - 对外 `categories`/`entries`（及派生）改为指向当前账本 data 的**可写 computed**；
   - `loadLedger` 走 `normalizeLedgerStore`（含旧数据迁移）；`saveLedger` 写 `LedgerStoreData`；
   - 新增 `createLedger/switchLedger/renameLedger/clearLedgerRecords/deleteLedger/guardLedgerYear`；
   - `addEntry/updateEntry/deleteEntry/addCategory/...` 内部写当前账本 data 后 `saveLedger`；
   - 保留现有 `toggleAmountVisibility`、`incomeCategories`/`expenseCategories` 等 API 签名不变。
4. **UI 切换器**：新建 `src/components/workbench/LedgerSwitcher.vue`（镜像 `BusinessLedgerSwitcher.vue`，读个人 store），嵌入 `WorkbenchLedger.vue` 头部月份条旁。
5. **设置弹框**：`AppSettingsDialog.vue` 加 `wb-ledger` 子 tab + rail 项 + 内容区（镜像 business 账本管理区块），接入个人 store 的账本 CRUD。
6. **回归**：`WorkbenchLedger.vue` 与 `ledgerCore` 原则上无需改；跑 `vue-tsc -b` + `vite build` 验证 0 类型错、构建通过。

## 9. 影响面与风险

- **低风险**：`WorkbenchLedger.vue`、所有 `ledgerCore` 统计函数——只要 store 对外 API（`entries`/`categories` 等）签名保持，无需改。
- **中风险**：store 内部结构重写 + 旧数据迁移；务必保证无账本/旧结构时降级为空态、由「创建引导」承接（参考 business `needsCurrentYearLedger`）。
- **注意**：当前 master 存在 `toolbox` 模块预存类型错误（`vue-tsc -b` 一贯报，与本次无关）；本次以 `vite build` 通过为交付判据，新增文件不得引入新类型错。
- **构建约束**：本机约 8GB，构建用 `NODE_OPTIONS="--max-old-space-size=4096" RAYON_NUM_THREADS=1`，空闲内存 <1.1GB 不硬跑；构建后 `git checkout -- src/composables/presetIcons.ts` 还原生成物。
