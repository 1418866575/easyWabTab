本文档给出**表结构设计**、**同步机制**、**渠道类型定义**三部分的详细方案。表名/结构落地采用需求文档 §4 的**方案 A（统一镜像表）**为主推；方案 B 的差异在 §2.4 单列。

## 1. 浏览器端 IndexedDB 现状盘点（事实基准）

数据库 `easy-web-tab`，版本 `DB_VERSION = 23`，全部 object store **无 keyPath**（out-of-line），绝大多数 store 用固定键 `'items'` 存一条 JSON；少数 store 按自定义键多记录存储。参与云同步的 store 如下（与 `src/composables/useIdb.ts` `IDB_*_STORES` 一致）：

| 类别 | object store 名（= 飞书 `store` 列取值） | 本地存储方式 | 同步信封/落点 |
|---|---|---|---|
| 核心 10 | `todos` `notes` `diary` `countdowns` `passwords` `health` `ledger` `settings` `business` `family` | 单条 `items` | `workbench.json` / `business.json` |
| 导航 | `nav` | **多记录**（键＝导航键，如 `user-sites`） | `nav.json` / `smart.json` / `blog-prefs.json`（按键分属） |
| 图标 | `icons` | 单条 `items`（数组） | `icons.json` |
| 学生 17 | `student_settings` `student_habits` `student_diary` `student_countdowns` `student_homework` `student_timetable` `student_plans` `student_review` `student_goals` `student_mistakes` `student_reading` `student_achievements` `student_rewards` `student_parent_tasks` `student_education` `student_health` `student_grades`（另 `student_images` 存 Blob，**不进云同步**） | 单条 `items` | `student.json` |
| 教师 | `teacher_workbench` | 单条 `items` | `teacher.json` |
| 博客 | `blog` | 单条 `items`（`BlogData`） | `blog.json` |
| 博客前台偏好 | `nav` 内键 `blog-prefs` | 多记录 | `blog-prefs.json` |
| 智能工作台 | `nav` 内 7 键（`smart-*`） | 多记录 | `smart.json` |
| **不进云同步** | `snapshots`、`iconcache`、`books`（本机上传书） | — | 永不推送飞书 |

> 结论：云端飞书表的 `store` 列取值集合 = 上表所有参与同步的 store 名；`key` 列对单记录 store 取常量 `'items'`，对 `nav` 取其真实键（`user-sites` 等）。

## 2. 表结构设计

### 2.1 飞书统一镜像表（方案 A，主推）

复用你提供的现成数据表：

- **Base 解析**：wiki 节点 `LMkywtydlilkGPkwySQckj2knrg` → `GET /wiki/v2/spaces/get_node` → `data.node.obj_token` 即 **app_token**；数据表 ID `tblP8YN0GyDAkxGV`（取自 URL `?table=`）。
- **API 域名**：自定义私有飞书域 `https://ccntnhpa9kme.feishu.cn/open-apis/...`（非 `open.feishu.cn`）。

表列结构（与 IndexedDB "key → value 容器"语义完全一致）：

| 飞书字段名 | 字段类型（Bitable type） | 含义 | 对应 IDB |
|---|---|---|---|
| `rowKey` | 文本（单行，设唯一索引） | 行主键 = `${store}#${key}`，用于幂等 upsert | —（合成） |
| `store` | 文本（单行） | object store 名（表名对齐） | object store 名 |
| `key` | 文本（单行） | 记录键，单记录 store 为 `items`，多记录为真实键 | IDB 键 |
| `value` | **多行文本** | `JSON.stringify(recordValue)` | IDB 值 |
| `clientId` | 文本（单行） | 写入设备 ID（现有 `WORKBENCH_DATA_VERSION` 之上的设备指纹），跨设备冲突识别 | 信封内 `clientId` |
| `updatedAt` | 日期（13 位毫秒时间戳） | 本地最后修改时间 | dirty/签名时间戳 |
| `syncedAt` | 日期（13 位毫秒时间戳） | 本次上云时间 | — |
| `channel` | 单选 | 写入渠道：`thirdPartyCloud` / `selfHosted` / `feishu`（便于多端混用审计） | — |

**结构一致性的含义**：
- "表名一致" → `store` 列取值与 IDB object store 名逐字相同（todos / notes / nav / student_homework …）。
- "结构一致" → 每行精确对应 IDB 的一条 `key→value` 记录；单记录 store 退化成 `key='items'` 的一行，多记录 store（`nav`）展开成多行。整张飞书表 = IDB 的扁平镜像，可无失真还原。

### 2.2 行示例

| rowKey | store | key | value（截断） | clientId | updatedAt | syncedAt | channel |
|---|---|---|---|---|---|---|---|
| `todos#items` | todos | items | `[{"id":"t1","title":"...","done":false,...}]` | `dev-7f3a` | 1760…000 | 1760…500 | feishu |
| `nav#user-sites` | nav | user-sites | `"[{\"id\":\"s1\",...}]"` | `dev-7f3a` | 1760…100 | 1760…500 | feishu |
| `student_homework#items` | student_homework | items | `{...}` | `dev-7f3a` | 1760…200 | 1760…500 | feishu |

### 2.3 超大值处理（约束见需求 §5）

- `icons`、`notes`、`ledger` 等 JSON 可能逼近飞书**单单元格 10 万字符**上限。
- 策略：推送前估算 `value` 字节长度；超限时对单 store 启用**分片行**（`rowKey = store#key#partN`，`value` 分块），拉取时按 `partN` 顺序拼接还原。分片元数据写入同表 `part` 列（整数，0=不分片）。

### 2.4 方案 B（字面同名多表）差异

若确认采用方案 B，则新建专属多维表格，为 §1 每个参与同步的 store 各建一张同名表，列结构统一为 `key / value / updatedAt / syncedAt / clientId / channel`（无 `store` 列，因为表名已表达）。upsert 主键改为 `key`（单记录 store 仅一行 `items`）。建表走 `POST /bitable/v1/apps/{app_token}/tables` + `POST .../tables/{table_id}/fields`。其余同步机制与方案 A 完全一致。

## 3. 同步机制

### 3.1 传输层抽象（对现有引擎的最小侵入）

现有 `useCloudSync.ts` 直接调用 WebDAV（`davGet/davPut/davDelete` + `/api/webdav-proxy`）。新增抽象：

```ts
interface SyncTransport {
  // 推送一个"同步单元"（方案 A 下一单元 = 一个 store 的全部记录；方案 B = 一张表）
  pushUnit(unit: SyncUnit): Promise<void>
  // 拉取全部单元
  pullAll(): Promise<SyncUnit[]>
  // 校验连通性 / 凭据
  testConnection(): Promise<{ ok: boolean; message: string }>
}

interface SyncUnit {
  store: string        // object store 名
  entries: { key: string; value: unknown }[]
}
```

WebDAV 现有行为封装为 `WebDavTransport`（保持 `shouldUseDirect` / 代理逻辑不变）；新增 `FeishuBitableTransport`。上层同步调度（markDirty / 签名 / 静默阈值 / 冲突 UI）**渠道无关**，无需改动。

### 3.2 飞书鉴权与节点解析流程

```
1. 读取本机凭据：appId, appSecret, nodeToken(=LMky...), tableId(=tblP8...)
2. POST {domain}/open-apis/auth/v3/tenant_access_token/internal
     body: { app_id, app_secret }
     → { tenant_access_token, expire }   // 缓存，过期前复用（expire 秒）
3. GET  {domain}/open-apis/wiki/v2/spaces/get_node?token={nodeToken}
     Authorization: Bearer {tenant_access_token}
     → data.node.obj_type === 'bitable' ? data.node.obj_token : 报错
     （obj_token = app_token）
4. 之后所有 records 接口用 {app_token, tableId}
```

> 鉴权失败常见码：`99991679`（scope 不足，需在飞书后台给应用加"查看、评论、编辑和管理多维表格"等权限）、`1254040`（token 不存在/文档已删）、`99991672`（无该资源权限——须把应用加为**该知识库节点/多维表格的协作者**，或加为知识库管理员）。

### 3.3 推送（Push / Upsert）

1. 遍历 §1 全部参与同步的 store：
   - 单记录 store：`idbGet(store)` → 1 个 entry（`key='items'`）。
   - 多记录 store（`nav`）：`idbGetAllEntries('nav')` → N 个 entry（按 key）。
   - 特殊：博客前台偏好在 `nav['blog-prefs']`、智能工作台在 `nav['smart-*']`，随 `nav` 一并导出（与现有 `exportNav/exportSmart/exportBlogPrefs` 一致）。
2. 对每个 entry 计算 `rowKey = store#key`；`value = JSON.stringify(recordValue)`（必要时分片，见 §2.3）。
3. **幂等 upsert**：先 `POST .../records/search`（filter `rowKey = 当前值`，最多 500 行/页）查出现有 `record_id`；有则 `PUT .../records/{id}` 更新，无则 `POST .../records` 新增。批量走 `batch_create` / `batch_update`（单次 ≤500）。
4. 本地已删除的 key（相对上次同步快照）：`batch_delete` 对应 record_id。
5. 记录本次同步快照（`store#key → recordId/updatedAt`）到本机，供下次增量 diff。

### 3.4 拉取与合并（Pull / Merge）

1. `GET .../records`（分页拉全部行）→ 按 `store` 分组，还原每个 store 的 `entries`（分片行先拼接）。
2. 写回 IndexedDB，复用现有 import 语义，保证与 WebDAV 渠道行为一致：
   - `nav`（含 `user-sites` 等 10 同步键、`smart-*`、`blog-prefs`）→ `importNavData` / `importSmartData` / `importBlogPrefsData`（**只补不删**，防误删兜底）。
   - `student_*`（不含 `student_images`）→ `importStudentData`（单事务覆盖）。
   - `teacher_workbench` → `importTeacherData`（null 跳过）。
   - `blog` → `importBlogData`（按 id+updatedAt 合并，防发布状态被冲）。
   - 核心 9 + `icons` → 经 `importWorkbenchData` / `importIconsData`（保留本机 cloudSync 凭证、family/ledger/diary 兜底）。
3. 冲突识别沿用现有 `pushedSig` / `remoteTs` / 内容签名：若本地 dirty 且远端 `updatedAt` 较新 → 触发现有冲突 UI（或静默合并，依据 `cloudSyncSilentThreshold`）。

### 3.5 触发与节流

- 复用 `markDirty()` + 防抖 1.5s 的"保存即上云"（`cloudSyncAutoPush`）。
- 复用 `cloudSyncInterval` 定时间隔（分钟，0=仅触发式）。
- 飞书 records 接口 50/s、查询 20/s，批量 ≤500/次；推送循环内对批量请求做限速（如每批 sleep 200ms）避免触发频限。

## 4. 渠道类型定义

### 4.1 Settings 字段（改动 `src/types/index.ts` 的 `AppSettingsData`）

```ts
// 同步渠道类型（新增）
export type SyncChannel = 'thirdPartyCloud' | 'selfHosted' | 'feishu'

// 在 AppSettingsData 内新增：
cloudSyncChannel?: SyncChannel        // 渠道类型，缺省兼容旧数据：视为 'selfHosted'（原 WebDAV 行为）
// —— 飞书专属本机凭据（仅本机存储，绝不进入任何同步信封）——
cloudSyncFeishuAppId?: string        // 如 cli_aa4459b9ff79dce0
cloudSyncFeishuAppSecret?: string    // 仅本机
cloudSyncFeishuNodeToken?: string    // 知识库节点 token（URL /wiki/ 之后部分）
cloudSyncFeishuTableId?: string      // 数据表 ID（URL ?table= 之后部分）
cloudSyncFeishuAppToken?: string     // 解析缓存（可由 nodeToken 推导，存本机免重复解析）
```

> 现有 `cloudSyncUrl / cloudSyncUsername / cloudSyncPassword` 继续服务 `thirdPartyCloud` 与 `selfHosted`（二者传输都是 WebDAV，仅语义分类不同）。`cloudSyncEnabled` 总开关、`cloudSyncInterval`、`cloudSyncSilentThreshold`、`cloudSyncAutoPush` 三类渠道共用。

### 4.2 渠道 → 传输实现路由

```ts
function resolveTransport(channel: SyncChannel | undefined, settings: AppSettingsData): SyncTransport {
  if (channel === 'feishu') return new FeishuBitableTransport(settings)
  return new WebDavTransport(settings)   // thirdPartyCloud / selfHosted 共用 WebDAV
}
```

`hasSyncCredentials(settings)` 需按渠道分别判定：飞书渠道要求 `appId + appSecret + nodeToken + tableId` 齐备；WebDAV 渠道要求 `url + username + password` 齐备。

### 4.3 概念映射

| 渠道 | 存储后端 | 传输 | 凭据 |
|---|---|---|---|
| `thirdPartyCloud` | 第三方 WebDAV（坚果云等） | WebDAV（经 `/api/webdav-proxy` 或直连） | URL/用户名/密码 |
| `selfHosted` | 自建 nginx+Node WebDAV（16719/16718） | 同上 | 同上 |
| `feishu` | 飞书多维表格（Bitable） | Feishu Bitable REST | AppId/AppSecret/NodeToken/TableId |

## 6. 实现里程碑（建议顺序）

1. **M1 字段与路由**：`SyncChannel` 枚举 + settings 字段 + `resolveTransport` 骨架（飞书分支先抛"未实现"提示，保证编译通过、不影响现有 WebDAV）。
2. **M2 飞书传输核心**：`FeishuBitableTransport` 鉴权 + node 解析 + 单 store 推送/拉取（先打通 `todos` 单 store 端到端）。
3. **M3 全量镜像**：遍历 §1 全部参与同步 store，含 `nav` 多记录展开、分片、删除增量。
4. **M4 合并与冲突**：接入 import 语义 + 签名/remoteTs + 静默阈值 + 冲突 UI。
5. **M5 设置 UI + 文档**：渠道下拉、飞书凭据区块、更新使用文档。
6. **M6 验证**：`vue-tsc -b` 零新增类型错 + `vite build` 通过；浏览器实测（用你提供的凭据做一次真实双向同步，核对飞书表行与 IDB 一致）。
