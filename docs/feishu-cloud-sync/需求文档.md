# 飞书表格云同步 · 需求文档

> 分支：`20261016-feishu-sync-sifujiang`（基于 master `5ba1964`）
> 日期：2026-10-16
> 关联代码：`src/composables/useIdb.ts`（IndexedDB 层）、`src/composables/useCloudSync.ts`（WebDAV 同步引擎）、`src/types/index.ts`（AppSettingsData）

---

## 1. 目标（Goals）

1. **新增第三类云同步渠道**：在现有「WebDAV 云同步」之上，增加「飞书多维表格（Bitable）」作为云端存储后端，使 easy-web-tab 工作台数据可双向同步到飞书表格。
2. **表名与结构对齐 IndexedDB**：在飞书中建立与浏览器端 IndexedDB（`easy-web-tab` 数据库，v23）**表名、表结构完全一致**的数据表，保证本地存储与云端存储一一对应、可镜像还原。
3. **渠道类型字段化**：在云同步设置中新增「同步渠道类型」字段，明确覆盖三类：
   - **第三方云平台**（如坚果云等公开 WebDAV 服务）
   - **自建服务**（用户自托管的 nginx + Node WebDAV 代理，如本项目部署的 `16719/16718` 端口）
   - **飞书表格**（飞书多维表格 Bitable）

---

## 2. 范围（Scope）

### 2.1 在范围内（In Scope）

- **设置层**
  - `AppSettingsData` 新增 `cloudSyncChannel` 渠道枚举字段（三选一）。
  - 新增飞书专属本机凭据字段（App ID / App Secret / 知识库节点 token / 数据表 ID），**仅本机存储、不参与云同步信封**（与现有 `cloudSync*` 凭证字段一致策略）。
  - 设置弹窗新增「渠道选择」与「飞书凭据录入」UI，复用现有 Design Token 与 `AppSettingsDialog` 布局。
- **同步引擎**
  - 抽象出现有 WebDAV 传输层为可插拔 `SyncTransport` 接口（`pushEnvelope` / `pullEnvelope` / `listEnvelopes` 等语义），现有 WebDAV 实现保持不变。
  - 新增 `FeishuBitableTransport`，对接飞书开放平台：
    - 鉴权：`tenant_access_token`（自建应用身份，`app_id` + `app_secret`，无需把机器人加入知识库成员）。
    - 知识库节点解析：`wiki/v2/spaces/get_node` 由 node_token 取得 Bitable 的 `app_token`。
    - 记录读写：`bitable/v1/apps/{app_token}/tables/{table_id}/records` 的查询 / 批量新增 / 批量更新 / 批量删除。
  - 复用现有「脏标记（markDirty）+ 内容签名（pushedSig / settingsSig / remoteTs）+ 静默合并阈值 + 冲突 UI」机制，迁移到飞书渠道。
- **表结构设计**
  - 设计一张与 IndexedDB object store 完全对齐的飞书数据表（详见技术文档 §2 表结构设计）。
  - 首次同步将本地 IndexedDB 现有数据全量写入飞书；之后增量 upsert。
- **文档**
  - 更新 `云同步的使用.md`，补充飞书渠道配置与限制说明。

### 2.2 不在范围内（Out of Scope）

- 不改动现有 WebDAV（第三方云 / 自建服务）同步逻辑与信封契约。
- 不引入飞书「用户身份登录」（`user_access_token`）——统一用应用身份（`tenant_access_token`），配置更简单、无需人工扫码授权。
- 不做多端实时协作 / 行级冲突字段合并（沿用现有「信封级 / 记录级最后写入胜出 + 冲突提示」模型）。
- 不把**不参与云同步**的本地数据（如 `books` 本机上传书、`snapshots`、`iconcache` 大体积缓存）推上飞书。
- 不改变现有 9 个信封（`nav/workbench/business/student/teacher/smart/blog/blog-prefs/icons`）的对外契约；飞书渠道在「store/记录级」镜像 IndexedDB，与 WebDAV 的「信封文件级」是两套等价映射。

## 4. 关键决策点（待确认）

> 以下两点影响表结构设计，建议在进入编码前确认。

1. **"完全一致表名"的落地方式**
   - **方案 A（推荐，贴合你提供的单一数据表）**：用你给出的那张飞书表（`tblP8YN0GyDAkxGV`，挂在 wiki 节点 `LMkywtydlilkGPkwySQckj2knrg` 下）作为**统一镜像表**。IndexedDB 的每一个 object store（如 `todos`、`notes`、`nav`、`student_homework`…）作为该行的一个 `store` 列取值，配合 `key` 列（单记录 store 用 `items`，多记录 store 用真实键），`value` 列放 JSON 文本。→ 一张飞书表容纳全部 IDB 数据，表名/结构在行内还原。
   - **方案 B（字面"每张表同名"）**：在**新建的专属多维表格**里为 IndexedDB 的每个 object store 各建一张同名飞书表（约 40+ 张），列结构统一为 `key / value / updatedAt / syncedAt / clientId`。→ 表名与 IDB 完全一致，但需要新建 base（而非使用你给的现成那张表）。
   - 两份文档主推 **方案 A**（直接复用你提供的表，且天然支持 40+ store 的扩展）；如你坚持"每张飞书表与 IDB store 同名"，则切换为方案 B，我会另行给出建表脚本。

2. **飞书凭据存放**：沿用现有「云同步凭证仅本机（IndexedDB），不随信封上云」策略；飞书的 App Secret 同样仅存本机，不进入任何同步数据流。

## 5. 风险与约束

- **飞书 API 频率限制**：记录接口 50 次/秒（新增）、20 次/秒（查询）；批量接口单次上限 500 条。数据量大时需分页 + 限速。
- **飞书"数据同步表"限制**：若误用飞书内置的"外部数据源同步表"，API 禁止增删改。必须用**普通可编辑**多维表格（你提供的 `?table=` 深链即普通表，符合）。
- **单表行数上限**：飞书单表约 10 万行上限。IndexedDB 全部参与同步的数据拆成 store/key 行后远未触顶，但 `nav` 等键较多、且大体积 JSON（如 `icons`）可能逼近单元格 10 万字符上限 → 需对超大值做评估/拆分（见技术文档 §3.3）。
- **凭证安全**：App Secret 等同数据库写权限，仅本机存储，且建议飞书后台对该应用开启最小权限（仅"查看、评论、编辑和管理多维表格" + "查看、编辑和管理知识库" + "查看知识空间节点信息"）。
