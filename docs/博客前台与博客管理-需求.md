## 1. 背景与目标

### 1.1 现状

easy-web-tab 是一个**本地优先（Local-first）、纯前端**的一站式工作台，已具备：

- **内容记录能力**：便签（含分类/截止日/时光轴）、日记（多日记本、Markdown 正文、封面）、Markdown 编辑预览工具；
- **结构化管理能力**：教师工作台、销售记账、学生工作台、工具箱（110+ 工具）、智能工作台；
- **数据底座**：IndexedDB 持久化（DB `easy-web-tab`，当前版本 21）、CloudSync 信封式云同步、统一的 Design Token 与 UI 规范。

但现有内容是**写给自己的**：没有面向读者的呈现形态（文章化、可检索、可长期访问）、没有发布与治理能力（草稿/发布/下架/定时）、没有互动能力（评论、审核、防刷）。

### 1.2 目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | **读者侧可用** | 陌生人打开站点即可浏览、检索、阅读、分享，形成完整阅读闭环（评论本期不做） |
| G2 | **作者侧高效** | 一个后台完成「写 → 存草稿 → 预览 → 发布 → 治理」，写作到上线不超过 5 步 |
| G3 | **管理侧可控** | 文章状态、敏感内容、分类标签、数据指标均可治理，规则可配置而非硬编码 |
| G4 | **工程不失控** | 完全沿用既有技术栈与规范，不新增框架、不拆分独立应用、不引入服务端依赖 |

### 1.3 量化目标（用于验收）

| 指标 | 目标值 |
|---|---|
| 内容容量 | 单站点支持 ≥ 1000 篇文章、≥ 10000 次阅读计次不出现明显卡顿 |
| 写作路径 | 从「新建」到「发布成功」的主干点击/操作 ≤ 5 步 |
| 移动端 | 768px 以下前台与后台编辑核心链路完整可用 |
| 质量门禁 | 类型检查 0 错误（`npm run typecheck`）、生产构建通过、新增纯函数有配套自测脚本 |

## 2. 范围

### 2.1 本期范围（In Scope）

1. **博客前台**：首页信息流（列表/分页/排序）、文章详情页、关键词搜索、条件筛选（分类/标签/归档）、第三方分享。（**评论本期不做**，见 §2.2）
2. **博客管理**：文章新建与编辑、草稿自动与手动保存、预览、分类与标签管理、发布/下架/定时发布、后台列表检索、文章状态流转与发布审核规则、敏感词管理（**仅文章侧发布校验**）、本地身份与角色管理、数据统计看板、回收站。（**评论管理与黑名单本期不做**）
3. **配套**：角色与权限边界定义、数据模型定义、非功能要求（性能/SEO/移动端/内容安全/统计口径）、优先级与迭代计划、验收标准。

### 2.2 非目标（Out of Scope，本期不做）

| 项 | 说明 |
|---|---|
| 真实多读者的跨设备互动 | 当前为纯前端 SPA、无服务端；**本期已决策不做评论**（见下方「评论」行与 R1），该风险本期不成立；未来若启用评论，需服务端支撑并另立项目 |
| 第三方登录 / OAuth / 短信邮箱验证 | 同上，需服务端 |
| SSR / SSG / Nuxt 等渲染框架 | 不引入新框架，见待确认项 R3 |
| 赞赏打赏、付费阅读、会员等级 | 商业模式相关，不在本期 |
| 多人协同编辑、版本 diff、操作审计留痕（管理员可追溯的完整日志） | 列为远期可选 |
| **评论与全部互动能力**（发表 / 回复 / 审核 / 防刷 / 举报 / 黑名单禁言） | **产品决策：本期不做**（2026-10-11）。数据模型（§5.4 / §5.7）**保留作预留**，接口与用例标记为延后，后续启用时无需改动数据契约 |
| 第三方评论服务（Giscus / utterances / Disqus 等） | 属外部服务依赖，本期不引入 |
| 评论邮件/站内实时通知推送 | 随评论一并延后 |
| 图片 CDN、视频托管、AI 生成封面 | 仅支持本地图片，见 §8.4 |

## 3. 术语

| 术语 | 定义 |
|---|---|
| 文章（Article） | 一条可对外展示的内容实体，含 Markdown 正文与元数据 |
| 草稿（Draft） | 尚未进入已发布状态的文章，含自动保存快照 |
| 已发布（Published） | 对游客/注册用户可见的文章 |
| 已下架（Offline） | 曾发布但主动撤回的文章，对外不可见、对内可再次上线 |
| 定时发布（Scheduled） | 已设定发布时间、到点自动转已发布的文章 |
| 待审核（Reviewing） | 提交发布后等待管理员通过的中间状态 |
| Slug | 文章的 URL 友好标识，用于详情页永久可读、可分享的地址 |
| 摘要（Excerpt） | 列表展示用的简短描述，可自动截取或手工填写 |
| 封面（Cover） | 文章主图（图片或纯色/渐变占位） |
| 置顶（Pinned） | 在前台列表中固定靠前的文章 |
| 评论（Comment） | 读者对文章发表的留言，含一级评论与回复 |
| 评论审核（Audit） | 管理员/作者判定评论为通过、驳回或垃圾的行为 |
| 敏感词（Sensitive Word） | 命中后按配置策略处置的词库条目 |
| 本地会话（Local Session） | 在当前浏览器会话内登录产生的角色身份，**不跨设备、不由服务端签发** |
| 软删除（Soft Delete） | 标记删除而非物理删除，进入回收站，可恢复或彻底删除 |
| 信封（Envelope） | 云同步的分片数据包单位 |
| Local-first | 数据主副本在访问者浏览器本机，服务端仅做同步通道 |

## 4. 角色定义与权限边界

### 4.1 角色总览

| 角色 | 身份来源 | 典型场景 | 是否需登录 |
|---|---|---|---|
| **游客（Visitor）** | 未登录或会话过期的默认身份 | 从搜索结果/分享链接进来，纯浏览阅读 | 否 |
| **注册用户（Reader）** | 在本机完成注册并以口令登录后获得（本机读者身份） | 身份体系保留；本期无专属能力（随评论启用后生效） | 是（本机登录） |
| **作者（Author）** | 被分配 `author` 角色的本地身份 | 内容生产者：写作、管理自己文章 | 是 |
| **管理员（Admin）** | 被分配 `admin` 角色的本地身份（站点所有者，不删除） | 内容治理：全量文章、分类标签、敏感词（文章侧）、角色、设置、看板 | 是 |

角色关系：**管理员 ⊇ 作者 ⊇ 注册用户 ⊇ 游客**（能力呈包含关系，不交叉）。

### 4.3 本地会话规则

| 编号 | 规则 |
|---|---|
| S1 | 未识别身份一律按**游客**处理，前台全部只读能力可用 |
| S2 | 访问后台路由 `/blog/admin` 必须是**作者或管理员**，否则回落到前台首页并给出明确提示（「无权限访问后台，请切换为作者/管理员身份」） |
| S3 | 身份凭证复用项目既有的本地口令/验证串校验思路（与密码库主密码、学生家长 PIN 同源），**不明文存放口令**，校验失败次数受限并给出锁定冷却 |
| S4 | 会话默认 **120 分钟**无操作自动回落为游客（可在博客设置中配置，取值区间 15–1440 分钟） |
| S5 | 切换身份必须重新校验；同一时刻仅一个有效会话身份 |
| S6 | 所有角色切换、敏感操作（删除/彻底删除/角色变更）需记录**操作流水**（本地留存，用于后台最近操作展示） |
| **安全边界声明** | 本期角色与权限是**界面级控制**，不构成安全边界：全部数据物理上位于访问者本机浏览器内，具备本地数据访问能力的人可绕过前端限制。文档与界面需明确提示「本机博客，不适合托管保密内容」 |

## 5. 关键数据模型

> 说明：以下类型为**数据契约定义**（字段、含义、校验），用于对齐存储与同步结构，不代表实现代码。

### 5.1 文章（Article）

```ts
export type ArticleStatus = 'draft' | 'reviewing' | 'scheduled' | 'published' | 'offline' | 'rejected'
export type CommentPolicy = 'open' | 'closed'

export interface BlogArticle {
  id: string            // 主键，前缀 'ba_'
  slug: string          // URL 友好标识，全站唯一
  title: string         // 标题
  subtitle?: string     // 副标题
  excerpt: string       // 摘要（手工填写优先，缺失时由正文截断生成）
  coverImageId?: string // 封面图（指向图片 store 的 id）
  coverKind: 'none' | 'image' | 'gradient' | 'solid'
  coverToken?: string   // 纯色/渐变占位所用的 Token 名（沿用既有主题变量）
  contentMarkdown: string
  status: ArticleStatus
  authorId: string
  categoryId?: string
  tagIds: string[]
  pinned: boolean
  allowComment: CommentPolicy
  viewCount: number
  commentCount: number  // 冗余计数（本期恒为 0，随评论启用后维护）
  readingMinutes: number // 派生：由正文字数/代码块估算
  createdAt: string
  updatedAt: string
  publishedAt?: string
  scheduledAt?: string
  offlineAt?: string
  deletedAt?: string
  seoTitle?: string
  seoDescription?: string
  auditRemark?: string   // 最近一次审核意见
  auditBy?: string
  auditAt?: string
  revision: number       // 每次保存自增，用于草稿冲突判定
}
```

**字段字典与校验**

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| `id` | string | ✔ | `ba_` 前缀，全局唯一 |
| `slug` | string | ✔ | 允许小写字母、数字、连字符；长度 1–80；全站唯一；不得与保留路由名冲突（如 `admin`、`search`、`archive`） |
| `title` | string | ✔ | 1–100 字符，首尾去空格，不允许纯空白 |
| `subtitle` | string | — | ≤120 字符 |
| `excerpt` | string | ✔ | 存储时可为空串（空时由正文前 N 字自动生成，N 默认 120） |
| `contentMarkdown` | string | ✔ | 非空；长度上限 200000 字符；单张内联图片受图片体积限制约束 |
| `status` | enum | ✔ | 取值见状态机 §7.1 |
| `categoryId` | string | — | 必须指向存在的分类；分类被删除时置空而非连带删除文章 |
| `tagIds` | string[] | — | 每个标签数量上限 10；指向不存在的标签时自动忽略（容错，不报错） |
| `pinned` | boolean | ✔ | 同时置顶数量上限 3，超出时拒绝并提示 |
| `allowComment` | enum | ✔ | 默认 `open` |
| `viewCount` | number | ✔ | ≥0；同一浏览器同一文章按时间窗口去重（默认 30 分钟）累加 |
| `commentCount` | number | ✔ | 本期恒为 0（预留，随评论启用） |
| `scheduledAt` | string | — | 仅 `scheduled` 状态必填；必须晚于当前时间 |
| `seoTitle` / `seoDescription` | string | — | ≤60 / ≤160 字符，缺省时回落到 `title` / `excerpt` |
| `revision` | number | ✔ | 正整数，保存即自增 |

### 5.2 分类（Category）

```ts
export interface BlogCategory {
  id: string        // 前缀 'bc_'
  name: string
  slug: string
  parentId?: string // 一级父子结构，最多两级
  description?: string
  order: number
  createdAt: string
  updatedAt: string
}
```

| 规则 | 说明 |
|---|---|
| C1 | 名称必填、≤30 字符、同一父级下不可重名 |
| C2 | 层级最多两级（`parentId` 指向的分类不得再有父级） |
| C3 | 删除分类：其文章 `categoryId` 置空；若有子分类，需确认后一并置为孤儿或提升层级（默认：子分类一并提升为顶级，行为需在确认框中明示） |
| C4 | 分类文章数 `articleCount` 为派生值，不在存储中冗余 |

### 5.3 标签（Tag）

```ts
export interface BlogTag {
  id: string      // 前缀 'bt_'
  name: string
```

### 6.1 博客前台（读者侧）

#### UC-F-01 浏览首页文章信息流

- **优先级**：P0
- **角色**：游客及以上

**前置条件**
1. 博客已完成初始化（存在至少 1 名管理员）；
2. 当前存在至少 1 篇 `status=published` 且 `publishedAt ≤ 当前时间` 的文章；
3. 浏览器已加载前台首页。

**主流程**
1. 读者进入博客前台首页；
2. 系统按当前排序规则（默认最新发布优先）取第 1 页文章；
3. 顶部展示博客名称、简介与全局入口（搜索、归档、标签）；
4. 列表按展示字段渲染文章卡片（见下表）；
5. 置顶文章固定排在结果最前，并带「置顶」标识；
6. 读者滚动阅读，底部提供分页控件（见 UC-F-02）。

**展示字段（列表卡片）**
封面图/占位色块、标题、副标题（有则显示）、摘要、分类名（有则显示）、标签（最多 3 个，超出显示 +N）、作者昵称、发布时间（相对时间 + 绝对时间悬浮）、阅读时长、阅读数。

**异常流程**

| 编号 | 情形 | 系统行为 |
|---|---|---|
| A1 | 无任何已发布文章 | 展示空态：图标 + 「还没有发布任何文章」+ 引导（如已登录且为作者/管理员，展示「去后台写第一篇」入口） |
| A2 | 存在文章但全部为草稿/待审核 | 同 A1，文案调整为「尚未有公开文章」 |
| A3 | 本地数据读取失败 | 保留空列表 + 明确错误提示 + 「重试」操作，不白屏、不自动清空数据 |
| A4 | 数据版本升级失败 | 提示「数据需要迁移/修复」，引导进入备份恢复流程，不允许写入半成品数据 |

**业务规则**：列表仅展示已发布且已到发布时间的文章；软删除与回收站文章绝不出现在前台。

#### UC-F-02 分页浏览与切换排序

- **优先级**：P0

**前置条件**：已进入任意列表页且结果数大于每页条数。

**主流程**
1. 读者在列表底部看到分页控件：共 N 条、上一页/下一页、页码、每页条数切换、跳转；
2. 点击页码/上一页/下一页 → 列表刷新且滚动位置平滑回到列表顶部；
3. 切换每页条数（默认 10，可选 10/20/50）→ 回到第 1 页并保持已选排序；
4. 通过浏览器前进/后退 → 恢复到上一次列表位置（沿用既有 `scrollBehavior` 恢复策略）；
5. 切换排序（最新发布 / 最早发布 / 最多阅读 / 标题 A-Z）→ 回到第 1 页；排序与分页、筛选条件在页面停留期间保持。

**异常流程**
- E1：跳转页码超出范围 → 自动夹取到边界页并提示；
- E2：浏览过程中文章被下架导致该页为空 → 自动回落到最后一页并轻提示「内容已更新」。

#### UC-F-03 按分类 / 标签 / 归档筛选

- **优先级**：P0

**前置条件**：存在至少一个非空分类或标签，或存在已发布文章（归档）。

**主流程**
1. 读者在侧边栏/工具栏选择分类（支持两级）、标签或归档月份；
2. 列表按该维度过滤，页面顶部给出面包屑式筛选条（可一键清除）；
3. URL 同步反映筛选维度，可直接复制分享；
4. 分类/标签页展示该维度的说明（分类描述/同标签文章数）；
5. 多重条件共存时按「先选先生效」叠加，筛选条支持单独移除某一条件。

**异常流程**
- E1：所选分类/标签下无已发布文章 → 展示该维度专属空态与「查看全部分类/标签」入口；
- E2：筛选条件指向已删除的分类/标签 → 回落全量列表并提示「该分类/标签已不存在」；
- E3：URL 参数缺失或非法 → 忽略非法部分，恢复正常列表，不报错。

#### UC-F-04 关键词搜索文章

- **优先级**：P0

**前置条件**：前台工具栏提供搜索入口。

**主流程**
1. 读者输入关键词（支持空格分词）后回车或点击搜索；
2. 系统按权重匹配：标题 > 副标题/摘要 > 标签 > 正文；
3. 结果页展示命中文段（关键词高亮）、文章元信息、命中位置说明；
4. 支持在结果中二次筛选分类/标签与排序（最近相关性 / 最新发布）；
5. URL 携带查询词，可分享与刷新保持；
6. 无结果时给出「未找到」+ 建议（减少关键词、清除筛选）。

**异常流程**
- E1：关键词为空 → 不执行搜索，给出提示；
- E2：关键词过长（>50 字符）→ 截断并在提示中说明；
- E3：搜索过程耗时较长 → 保留上一次结果并展示加载态，允许取消（不得阻塞 UI）。

**业务规则**：搜索范围仅限**已发布且已到发布时间**的文章正文与元数据；不返回草稿、回收站、评论内容。

#### UC-F-05 查看文章详情

- **优先级**：P0

**前置条件**：读者从列表/搜索/分享链接进入详情页。

**主流程**
1. 打开详情页，展示：封面/占位、标题、副标题、作者、发布时间、更新时间（仅在有更新时出现）、分类、标签、阅读时长、阅读数；
2. 正文按 Markdown 渲染，支持标题锚点与目录导航（正文含 ≥3 个二级标题时自动出现目录）；
3. 显示上一篇/下一篇导航（按发布时间序列）；
4. 展示相关文章推荐（同标签优先，其次同分类，最多 5 条）；
5. 阅读数按去重口径累加；
6. 页面向下滚动时展示阅读进度指示；
7. 文末提供分享区（UC-F-06）；文末评论区本期不提供（评论延后），可选择性展示作者联系方式（由博客设置配置）；
8. 页面标题、描述、Open Graph 元信息随文章同步更新（见 §8.2）。

**异常流程**
- E1：slug 不存在 → 展示 404 专用页，提供「返回首页/去搜索」入口；
- E2：文章状态非已发布（草稿、待审核、已下架、定时未到）→ 游客按 404 处理；作者/管理员可见并展示状态提示条与「编辑」入口；
- E3：文章被软删除 → 所有人（含作者）均按 404 处理，仅管理员可在回收站中查看；
- E4：正文含不受支持的语法/外链失效 → 降级为纯文本展示，不影响其余内容渲染。

**业务规则**：
- 正文渲染必须走**白名单过滤**（禁止裸 HTML 注入、禁止可执行脚本），详见 §8.4；
- 站内正文图片以本地资源为主，外链图片加载失败时展示占位而非破图；
- ~~关闭评论的文章不展示评论输入区~~（本期无评论区，随评论延后）。

#### UC-F-06 分享文章到第三方

- **优先级**：P1

**前置条件**：处于文章详情页（有可读 URL）。

**主流程**
1. 读者点击「分享」；
2. 面板提供：复制链接、二维码、第三方渠道（微博、QQ 空间、X/推特、邮件）；

4. 二维码展示当前页面地址（可在弹层中直接查看与保存）；

**异常流程**

#### UC-F-07 发表评论

> **本期不实现（延后）**：以下为预留设计，保留文本以备后续启用，不进入迭代计划与验收清单。

- **优先级**：延后

**前置条件**
1. 文章 `status=published` 且 `allowComment=open`；
2. 全局设置允许评论；本站「访客可评论」开关视设置而定；
3. 当前会话未被禁言。

**主流程**
1. 读者在评论区输入昵称（未登录时必填）、可选邮箱、正文；
2. 提交 → 系统进行校验（见业务规则）；
3. 校验通过后评论入库，按规则进入 `pending`（开启审核时）或直接 `approved`（关闭审核时）；
4. 界面明确告知结果：

   - 直接公开：立即出现在评论列表；
5. 未登录读者的昵称在本次会话内记住，下次评论免填；
6. 提交成功后输入框清空，列表中仅展示脱敏后的身份信息，不暴露邮箱明文。

**异常流程**

| 编号 | 情形 | 系统行为 |
|---|---|---|
| A1 | 昵称缺失或长度非法 | 行内提示具体原因，不提交 |
| A2 | 正文为空/超长 | 行内提示剩余字数限制，不提交 |
| A3 | 命中敏感词（策略=reject 或 strict 级） | 拒绝提交，提示「内容含受限词，请修改后再试」，高亮命中片段位置（仅提示位置，不展示词） |
| A4 | 命中敏感词（策略=review） | 允许提交但强制进入待审核，并提升其在审核列表中的排序 |
| A5 | 触发限频（间隔或小时上限） | 拒绝并提示剩余等待时间，倒计时结束后自动解禁 |
| A6 | 内容重复（与本机最近一条内容完全一致） | 拒绝并提示「请勿重复提交」 |
| A7 | 文章被关闭评论/中途下架 | 提交时提示「该文章已关闭评论/已下架」，输入区变为不可用 |
| A8 | 禁言用户提交 | 提示「当前身份已被限制评论」，不展示输入框 |
| A9 | 写入失败 | 保留输入内容，提示重试；不丢失用户输入 |

**业务规则（可量化默认值）**
- 同一会话发评最小间隔 **30 秒**；
- 同一会话每小时最多 **10 条**；单篇文章每会话最多 **5 条**；
- 正文长度 **2–1000** 字符；昵称 **2–24** 字符；
- 限频与「同一会话」的判定基于本机本地标识，**跨设备无效**（Local-first 约束，见待确认项 R1）；
- 邮箱仅本地留存，列表展示一律脱敏（如 `a***@example.com`）或不予展示；
- 所有评论默认需审核（默认 `commentAuditEnabled=true`）；作者自己发表的评论可选择免审（设置项）。

#### UC-M-03 编辑正文与元数据

#### UC-M-08 提交发布与审核

- **优先级**：P0

**前置条件**：文章存在标题与正文，且当前身份有该文章权限。

**主流程**
1. 作者点击「提交发布」→ 系统执行发布前校验（见业务规则）；
2. 校验通过：
   - 需审核（设置为开且提交人非管理员，或文章作者自设需复核）→ 状态转 `reviewing`，等待管理员审核；
   - 免审情形（管理员提交，或设置为免审且作者自审）→ 直接转 `published`，写入 `publishedAt`；
3. 管理员在「待审核」列表查看 → 通过（转 `published`）或驳回（转 `rejected` 并填写意见）；
4. 结果通知：后台列表状态更新、文章详情展示 `auditRemark`，作者可见自己文章的审核意见。

**业务规则（发布前必过校验）**
- 标题非空且 ≤100 字符；正文非空；slug 唯一且不命中保留字；
- 分类/标签引用有效（无效自动置空并提示修正）；
- 定时发布时间必须晚于当前时间；
- 命中敏感词：按设置（默认转人工复核）处理，策略 `reject` 时不允许发布并指出位置。

**异常流程**
- E1：校验不通过 → 逐条列出问题并定位到字段，不修改状态；
- E2：重复提交（已在 `reviewing`）→ 提示「已在审核中」，提供「撤回审核」；
- E3：审核时文章已被作者修改 → 提示内容已变更，审核需重新确认；
- E4：驳回后再次提交 → 覆盖上一次审核意见，重新进入队列。

4. 列表支持按状态筛选，状态用彩色标签区分（配色沿用既有 Design Token 与模块惯例，不得硬编码颜色）。

**异常流程**

- E2：对他人名下文章操作（越权）→ 操作不可见，直达不可用；

#### UC-M-10 定时发布

- **优先级**：P1

**主流程**

#### UC-M-11 后台文章列表检索与批量操作

- **优先级**：P0

**前置条件**：已有至少 1 篇文章（任意状态）。

**主流程**

- E2：批量操作中部分失败 → 完成后展示结果汇总（成功 N 条 / 失败 M 条及原因），不回滚已成功项；

#### UC-M-13 评论管理

## 7. 状态流转与发布审核规则

### 7.1 文章状态机

| 当前状态 | 允许动作 | 目标状态 | 允许角色 | 说明 |
|---|---|---|---|---|
| draft（草稿） | 提交发布 | reviewing 或 published | 作者（本人）/管理员 | 依审核规则决定是否免审 |
| draft | 定时发布 | scheduled | 作者（本人）/管理员 | 需设置未来时间 |
| draft | 删除 | 软删除（回收站） | 作者（本人）/管理员 | |
| reviewing（待审核） | 审核通过 | published | 管理员 | 写入 `publishedAt`、`auditBy` |
| reviewing | 驳回 | rejected | 管理员 | 必填审核意见 |
| reviewing | 撤回 | draft | 作者（本人）/管理员 | 退出队列 |
| rejected（未通过） | 重新编辑提交 | reviewing 或 published | 作者（本人）/管理员 | 覆盖上一次意见 |
| scheduled（定时） | 到点自动发布 | published | 系统 | 依UC-M-10 E2 处理失败 |
| scheduled | 取消/改为立即发布 | draft / published | 作者（本人）/管理员 | |
| published（已发布） | 编辑保存 | published 或 reviewing | 作者（本人）/管理员 | 是否重审由设置决定（默认：管理员编辑不重审；作者编辑已发布文章默认重审） |
| published | 下架 | offline | 作者（本人）/管理员 | 写入 `offlineAt` |
| offline（已下架） | 重新发布 | published | 作者（本人）/管理员 | 更新 `publishedAt` |
| offline | 删除 | 软删除 | 作者（本人）/管理员 | |
| 任意状态 | 恢复（仅回收站可见） | 回到删除前状态 | 管理员 | slug 占用按 E2 处理 |
| 仅在回收站 | 彻底删除 | 物理删除 | 管理员 | 级联清理图片引用（评论启用后一并清理） |

**不可达转移**（系统应禁止）：`published → draft`（必须先下架）；非法状态值在 `normalizeBlogData()` 时统一兜底为 `draft`。

### 7.2 文章发布审核规则

| 编号 | 规则 |
|---|---|
| R-A1 | **管理员**提交发布默认免审，直接 `published`（可通过设置改为需二次确认） |
| R-A2 | **作者**提交发布是否需由管理员审核，由博客设置 `reviewRequiredForAuthor` 控制（默认：**需要审核**） |
| R-A3 | 已发布文章被作者再次编辑并保存时，默认重新进入审核；管理员编辑则不重审（可配置） |
| R-A4 | 命中敏感词：策略 `review` → 强制进人工队列并置顶显示；策略 `reject`/严格级 → 不允许发布 |
| R-A5 | 定时发布任务到点执行时，需重新执行发布前校验；失败则转 `rejected` 并记录原因 |
| R-A6 | 审核意见对作者可见，对读者不可见 |
| R-A7 | 同一文章重复提交时，取最新一份内容与 `revision` 进行审核 |

### 7.3 评论状态机

> **本期不实现（延后）**：以下状态机为预留设计，随评论能力启用时生效。

| 当前状态 | 允许动作 | 目标状态 | 允许角色 |
|---|---|---|---|
| pending（待审核） | 通过 | approved | 作者（本人文章下）/管理员 |
| pending | 驳回 | rejected | 作者（本人文章下）/管理员 |
| pending | 标记垃圾 | spam | 作者（本人文章下）/管理员 |
| approved | 驳回/标记垃圾 | rejected / spam | 作者（本人文章下）/管理员 |
| 任意状态 | 删除（读者自助） | hidden-deleted（本地隐藏留痕） | 注册用户（仅本人评论）/管理员 |
| spam / rejected | 恢复 | approved | 管理员 |
| rejected / spam | 彻底删除 | 物理删除 | 管理员 |

**计数规则**：`commentCount` 仅统计 `approved`；`hidden-deleted`、`pending`、`rejected`、`spam` 不计数，也不在前台展示；例外：读者本人可对自身的 `pending` 评论看到「审核中」可见提示。

## 8. 非功能需求

### 8.1 性能

| 编号 | 指标 | 目标值（本机/默认数据规模） | 测量方式 |

| N-C8 | 导出文件默认脱敏（邮箱）；导出前提示「导出文件包含站点内容，请妥善保管」 |
| N-C9 | **安全边界声明**：前端权限为界面级控制，本机数据可被具备设备访问能力的人读取；界面需在博客设置/初始化向导明确提示，默认不存放涉密内容 |
| N-C10 | 无服务端，故不存在服务端侧 CSRF/越权接口攻击面；但所有入口仍需沿用既有守卫思路做权限收敛 |


### 8.5 数据统计口径

| 指标 | 定义 | 口径说明 |
|---|---|---|
| PV（阅读数） | 详情页被打开的次数 | 同一浏览器同一文章 30 分钟窗口内重复访问计 1 次 |
| UV | 去重访问者数 | 本地口径：以本机本地标识去重，**不代表真实独立访客**（无服务端，需在界面注明） |
| ~~文章评论数~~ | 延后 | 随评论启用后按 `approved` 统计，回复计入所属文章 |
| ~~待处理评论~~ | 延后 | 随评论启用后统计 `pending` |
| 发布/阅读趋势 | 最近 7/30 天按天的发布数与阅读增量 | 数据缺失天补 0，图表取样点上限 30 |
| Top 榜 | 按阅读数降序的前 10 篇文章 | 仅统计已发布文章 |

### 8.6 可访问性

| 编号 | 要求 |
|---|---|
| N-A1 | 主要交互可键盘到达（列表项、分页、搜索、分享、编辑器工具栏），焦点样式可见 |
| N-A2 | 图片具备 alt；图标按钮具备可读标签 |
| N-A3 | 文本与背景对比度满足 WCAG AA 级（沿用既有 Token 组合，不新增低对比色） |
| N-A4 | 状态变化有可读提示（含轻提示与行内错误说明），不依赖纯颜色表达状态 |

### 8.7 可靠性与兼容

| 编号 | 要求 |
|---|---|
| N-R1 | IndexedDB 写入失败需可感知（明确提示 + 重试），**禁止静默吞写** |
| N-R2 | 旧数据兼容：`normalizeBlogData()` 逐字段兜底，非法状态/id 重复均自愈，不抛错 |
| N-R3 | 首次进入未初始化时展示初始化向导，不阻塞导航站其它模块使用 |
| N-R4 | 升级到新 DB 版本不影响既有模块数据；版本迁移过程可分步骤执行，失败时不半途写入 |
| N-R5 | 部署：新增路由需沿用现有 SPA 回落配置（静态托管与容器部署两侧同步确认），分享链接必须可直接打开 |
| N-R6 | 构建：低内存环境（如 1.87GB 服务器）构建需沿用现有内存自适应策略，博客模块不得额外引入构建期重依赖 |

## 9. 优先级与迭代计划

### 9.1 优先级方法（MoSCoW）

- **P0 / Must**：没有它模块不可用（阅读闭环 + 写作发布闭环 + 权限收敛）
- **P1 / Should**：显著影响体验与可控性（分享、回复、定时、回收站、敏感词、身份管理、设置）
- **P2 / Could**：锦上添花（归档/标签墙、举报、看板、Markdown 批量导入导出、SEO 增强）

### 9.2 迭代计划

| 迭代 | 版本 | 目标 | 包含用例 / 事项 | 交付判据 |
|---|---|---|---|---|
| I1 | v1.0 MVP | **能写能看** | UC-F-01~06、UC-M-01~09、UC-M-11；数据模型落地（评论类型仅预留不落库）；IDB store 与 DB 版本升级；路由懒加载与 SPA 回落 | 完成前后台闭环，≥1 篇文章从写作到阅读全链路贯通；类型检查 0 错、构建通过 |
| I2 | v1.1 | **可治理** | UC-M-10、UC-M-12、UC-M-14（文章侧）、UC-M-15、UC-M-16；性能与移动端专项 | P1 用例全部通过；移动端断点下的发布链路可用 |
| I3 | v1.2 | **可运营** | UC-F-10、UC-M-17、UC-M-18；SEO 增强（sitemap/robots/结构化数据）；可选构建期预渲染（待 R3） | P2 用例通过；sitemap 可被抓取验证 |
| I4 | v2.0（待定） | **评论与互动** | UC-F-07~09、UC-M-13、黑名单禁言、评论侧敏感处置；**必须先解决 R1**（第三方评论服务与轻量服务端二选一），届时另行立项 | 另行立项，不在本期范围内 |

## 10. 验收标准（可量化）

### 10.1 功能验收

| 编号 | 验收项 | 判定标准 |
|---|---|---|
| V-F1 | 首页信息流 | 已发布且到时的文章按排序展示；草稿/待审/定时/下架/回收站文章**零泄漏**到前台 |
| V-F2 | 分页与排序 | 每页默认 10 条；切 20/50 正确；四种排序结果与预期一致；前进后退恢复列表位置 |
| V-F3 | 搜索 | 标题/摘要/标签/正文均可命中并高亮；仅返回已发布文章；性能满足 N-P2 |
| V-F4 | 筛选 | 分类（两级）、标签、归档条件可叠加且 URL 可分享；非法参数不报错 |
| V-F5 | 详情与 404 | slug 直达正常；草稿/下架对游客按 404、对作者/管理员可见提示；软删除对所有角色 404 |
| V-F6 | 分享 | 复制链接与二维码可用；剪贴板不可用时降级提示；第三方渠道新标签打开；移动端唤起系统分享（支持时） |
| V-F7 | ~~评论~~ | **本期不验收**（延后至 I4） |
| V-F8 | ~~回复~~ | **本期不验收**（延后至 I4） |
| V-F9 | 权限 | 游客直达 `/blog/admin` 被回落并提示；作者只见自己文章（≥2 账号交叉验证 1 次）；作者不可编辑他人文章 |
| V-F10 | 会话 | 120 分钟超时回落；连续失败 5 次触发 5 分钟冷却；至少 1 名管理员不可被删除/降级 |
| V-F11 | 写作与草稿 | 自动保存 3 秒防抖且不阻塞输入；刷新/离开前保住内容；草稿冲突三选一处理正确 |
| V-F12 | 预览 | 前台同构渲染，不产生阅读数、不改变状态、不对外可见 |
| V-F13 | 分类标签 | 同级重名被拒；删除分类不会删除文章（N 篇转未分类，数量需与实际一致）；删除标签不删文章 |
| V-F14 | 发布与审核 | 作者提交进 `reviewing`；管理员通过→`published`（写入发布时间）；驳回→`rejected` 且必填意见；未通过发布前校验则不流转 |
| V-F15 | 下架与再发布 | 下架后前台立即不可访问（含旧 URL）；统计数据保留；再发布时间更新正确 |
| V-F16 | 定时发布 | 到点自动发布，发布时间按计划时间回填；校验失败转 `rejected` 并记录原因 |
| V-F17 | 回收站 | 软删除不计入常规列表；管理员可恢复/彻底删除；彻底删除级联清理图片引用并有二次确认 |
| V-F18 | ~~评论管理~~ | **本期不验收**（延后至 I4） |
| V-F19 | 敏感词 | `review` 与 `reject` 策略、严格级优先生效；命中记录可查 |
| V-F20 | SEO 基础 | 每页 title/description/canonical 动态生效；sitemap 仅含已发布文章；robots 可被访问 |

### 10.2 非功能验收

| 编号 | 验收项 | 判定标准 |
|---|---|---|
| V-N1 | 性能 | 满足 §8.1 全部指标（N-P1~N-P7），以 1000 篇文章的构造数据验证 |
| V-N2 | 包体 | 博客路由懒加载；启用前后导航站首屏产物体积增幅 ≤ 0 |
| V-N3 | 移动端 | 768px 以下完成「浏览 → 搜索 → 后台写稿发布」全链路；触控目标达标；滚动容器符合页面级滚动约定 |
| V-N4 | 内容安全 | 输入含脚本的 Markdown，渲染结果不含可执行脚本，正文不得出现可执行脚本，事件属性被剥离；外链防护属性齐全；导出文件邮箱脱敏 |

| V-N7 | 部署 | 新路由在生产静态托管与容器部署两侧均可直接打开（含刷新与分享链接） |
