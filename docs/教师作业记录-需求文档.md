# 教师工作台 · 作业记录 需求文档（精简版）

> 状态：需求草稿（待评审）
> 目标：在教师工作台增加「作业记录」模块，**只关注未交作业的同学**。布置作业时按班级名册为每位同学生成一条独立的未交记录；同学补交后由老师**手动**把该记录状态改成"已补交"。不做自动追踪、不做已交同学的建模。

---

## 1. 设计原则（避免过度设计）

- **只存未交**：不建模"已交"同学，系统里只有"未交记录"。
- **每条记录对应一个人**：一次作业 × 一位未交同学 = 一条独立记录，带学生信息冗余副本。
- **补交靠人工**：系统不自动流转状态。同学交了，老师手动把该记录标记为"已补交"（可填补交时间/备注）。
- **无批量自动逻辑、无提交方式/批改/成绩/家长签字等扩展**——本期不做。

---

## 2. 数据模型

沿用既有范式，挂在 `TeacherData.groups[semesterId][classId]` 的数据桶里：

```ts
// src/types/teacher.ts —— ClassBucket 新增：
export interface ClassBucket {
  // ...既有字段...
  homeworks: TeacherHomework[]   // ← 本班本学期作业记录
}
```

### 2.1 作业（元数据）

```ts
export interface TeacherHomework {
  id: string          // 前缀 thw_
  subject: string     // 学科
  title: string       // 标题，必填
  content?: string    // 作业要求 / 描述
  assignDate: string  // 布置日期 'YYYY-MM-DD'，必填
  dueDate: string     // 截止日期 'YYYY-MM-DD'，必填
  createdAt: string
  updatedAt: string
  misses: TeacherHomeworkMiss[]   // 每位未交同学一条
}
```

> 不设置"收集中/已截止/已归档"等状态字段——作业以截止日期为准，避免多余状态机。

### 2.2 未交记录（每人一条，独立）

```ts
export type HomeworkMissStatus = 'pending' | 'madeup'
// pending = 未交；madeup = 已补交（人工标记）

export interface TeacherHomeworkMiss {
  id: string          // 前缀 thwm_
  studentId: string   // 关联 Student.id（主键，杜绝重名错配）
  studentName: string // 姓名冗余副本（名册变动后仍可读）
  studentNo?: string  // 学号（冗余副本，便于导出/核对）
  status: HomeworkMissStatus
  madeUpAt?: string   // 补交时间（人工填写，可选）
  note?: string       // 备注
}
```

### 2.3 派生（不持久化）

| 指标 | 算法 |
|---|---|
| 未交人数 | `misses.filter(m => m.status==='pending').length` |
| 已补交人数 | `misses.filter(m => m.status==='madeup').length` |

## 3. 功能与交互

### 3.1 页面入口
- 新增 `TeacherPageKey = 'homework'`（作业记录），归入**基础功能**（科任也布置作业，非班主任专属）。
- 随"当前学期 + 班级"切换联动。

### 3.2 作业列表
- 展示本班作业：`学科 · 标题`、`布置日→截止日`、`未交 N / 已补交 M`。
- 支持：新建、打开详情、删除（走既有 `tombstones` 机制）。

### 3.3 新建作业（核心生成逻辑）
- 表单：学科、标题（必填）、要求、布置日、截止日。
- 提交时：从当前 `bucket.students` **查询每位同学信息**，为每人生成一条 `TeacherHomeworkMiss`（`status='pending'`，写入 `studentId/studentName/studentNo`），挂到该作业 `misses` 下。

### 3.4 详情：未交名单
- 顶部：作业元信息 + `未交 N / 已补交 M`。
- 列表：每位未交同学一行 —— `学号 / 姓名 / 状态 / 补交时间 / 备注 / 操作`。
- 每行操作：
  - **标记为已补交**：状态置 `madeup`，可顺带填 `madeUpAt` / `note`。
  - **撤销补交**（可选）：改回 `pending`。
- 底部：复用现有 `ewt-dialog-footer`（取消/保存）。

### 3.5 导出未交名单
- 一键复制/下载当前作业未交同学名单（学号 + 姓名），便于发群催交。

---

## 4. 集成与约束

- **云同步**：随 `groups[sem][cls]` 数据桶自然同步，无需单独处理；遵循既有"只增不删 + tombstone"机制。
- **纯函数**：`teacherCore.ts` 新增 `normalizeHomework` / `initMissesFromRoster`（按名册生成未交记录）/ `countMisses`。store 薄委托（与 `leaves` 同范式）。
- **命名/样式**：复用项目既有 token 与组件（状态色、分页、弹框底栏、空态等）。
- **校验**：标题必填、布置日 ≤ 截止日、学生信息取自名册；保存前 `normalize`。

---

## 5. 不在本期范围（明确不做）

- 不建模"已交"同学、不做提交方式/批改/成绩/家长签字。
- 不做自动状态流转、逾期自动标红、批量自动标记。
- 不做多班级同布、作业模板、与学生端 `StudentHomework` 联动。

> 以上若后续需要再加，按既有范式增量扩展即可。

---

## 6. 已确认决策

1. **可见范围**：班主任、代课老师都能用 → **全员可见**（不放入 `TEACHER_HEAD_ONLY_PAGES`）。
2. **导出方式**：下载 **Excel 文件**（复用 `teacherExcelCore.exportExcel()`）。
3. **补交时间**：默认**留空，由老师手填**（不自动取当前时间）。

### 7.2 关键实现要点

- **创建时生成记录**：`addHomework` 调 `initMissesFromRoster(bucket.students)`，为每位在册同学生成一条 `status='pending'` 的 `TeacherHomeworkMiss`（写入 `studentId/studentName/studentNo`）。
- **补交人工改**：「标记为已补交」→ `markMadeup`，置 `status='madeup'` + 写入 `madeUpAt`/`note`（默认留空，手填）。
- **导出 Excel**：`exportMissesExcel` 组装 `sheets`，仅含 `status==='pending'` 的同学，调 `exportExcel(\`未交名单_${标题}\`, [sheet])` 下载 `.xlsx`。
- **学科来源**：新建表单学科用 `teacher.subjects`（已有）作下拉候选，缺省空、可手填，避免过度设计。

### 7.3 风险与注意

1. **旧数据兼容（必做）**：`normalizeTeacherData` / `emptyBucket` 必须把 `homeworks` 默认成 `[]`，否则升级后历史 `ClassBucket` 读取 `homeworks` 为 `undefined` 会报错。必要则 `TEACHER_SCHEMA_VER` 进位并在 normalize 里兜底。
2. **云同步**：`homeworks` 在 `groups[sem][cls]` 桶内，随既有信封自然同步；删除走 `tombstones`。
3. **Excel 下载**：走既有 `teacherExcelCore.exportExcel`，已验证可用，无需引新依赖。
4. **名单位置**：未交名单以"创建作业时快照的名册"为准；中途插班生不回插历史作业（与需求文档 §2.3 说明一致）。
