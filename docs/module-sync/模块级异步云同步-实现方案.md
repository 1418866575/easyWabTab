# 模块级异步云同步 — 实现方案与关键逻辑

> 目标：在左上角「工作台切换入口」切换模块时，自动、异步、按模块作用域地做一次云同步——
> **离开模块 → 落快照 → 上传该模块数据**；**进入模块 → 拉取该模块数据**。
> 全程不阻塞导航、不弹窗、不 loading；失败静默降级并可重试；模块间数据互不影响。

---

## 一、现状盘点（已用代码核实）

| 关键事实 | 证据 |

## 三、进入 / 离开的调用时机

切换是 `router.push`，因此挂钩**路由守卫**（覆盖 Alt+N 热键、浏览器的前进/后退等所有切换路径，无需改 `WorkbenchSwitcher.vue`）。

```ts
// 离开：必须在 beforeEach —— 此时组件还挂载着，才能抓到"未保存的编辑内容"
router.beforeEach((to, from) => {
  const leaveKey = moduleKeyOf(from.name)
  if (leaveKey && leaveKey !== moduleKeyOf(to.name)) {
    void moduleSync.onLeave(leaveKey)   // 不 await，导航立即继续
  }
  return true
})

// 进入：afterEach，目标模块已确定，拉该模块数据
router.afterEach((to) => {
  const enterKey = moduleKeyOf(to.name)
  if (enterKey) void moduleSync.onEnter(enterKey)   // 不 await
})
```

**为什么「离开」必须在 `beforeEach`**：`BlogEditor` 的草稿防抖保存依赖组件实例；若等到 `afterEach`，组件已卸载、flush 回调已注销，草稿就丢。`beforeEach` 里**同步触发** flush（函数立刻开始执行，组件仍在），随后导航立即放行，不等待 flush 完成。

**离开与进入相互独立**：两者是队列里两个独立任务，各自有独立的失败/重试生命周期；一个失败不影响另一个，也不影响导航。

时序：

```
切换瞬间
  ├─ beforeEach: 触发 flush(离开模块)  ──► 写 IDB（快照）
  │                └─► 入队 Task{type:'push', module:离开模块}  (await flush 后再导出)
  ├─ router.push 确认，动画/渲染开始（不受影响）
  └─ afterEach:  入队 Task{type:'pull',  module:进入模块}
队列串行执行：push(A) → pull(B)，全程后台
```

## 四、异步调度：防抖 + 串行队列 + 世代（epoch）

新增 `src/composables/useModuleSync.ts`（单例编排器）：

```ts
interface ModuleTask { key: string; type: 'push'|'pull'; module: string; epoch: number }
```

1. **防抖（debounce）**：按 `(type, module)` 维 600ms。快速连切 A→B→C 时，同一 key 重复入队只保留最后一次，中途的被取消。
2. **串行队列（single-flight）**：全局一条 Promise 链，同一时刻只有一个同步任务在跑——避免对同一信封并发 PUT/GET 造成脏覆盖（需求 4 明确认可"串行队列"）。
3. **世代校验（epoch）**：每个任务带全局递增 epoch；任务真正要**落盘/应用远端数据**前再校验一次 epoch，若已被更新的任务取代则**丢弃结果**，防止陈旧响应覆盖新数据（等价于"请求取消"，但无需改造 HTTP 层）。
4. **不阻塞**：任务永不 `await` 在导航链路上；内部不使用任何弹窗/loading；`silent` 全程为 `true`。

> 竞态补充：模块推送与既有 `markDirty → 1.5s 全局自动推送` 可能撞车。方案是让二者共用同一把"同步锁"，全局推送遇到模块任务在跑时排队而非并发（详见第八节）。

## 五、状态快照（需求 3）

**快照 = 先把"未落盘的改动"强制写进 IndexedDB，再从 IDB 导出信封**。这样上传的一定是切换瞬间的完整状态。

提供**模块 flush 注册表**，各模块按需注册：

```ts
// useModuleSync.ts
registerModuleFlush(moduleKey, fn: () => Promise<void> | void): () => void  // 返回注销函数

async function snapshot(moduleKey: string): Promise<void> {
  const jobs = flushers.get(moduleKey) ?? []
  await Promise.allSettled(jobs.map(fn => fn()))   // 单个 flush 失败不拖垮其他
  // 之后再 exportLocal()，读到的必是最新落盘状态
}
```

注册点：
- `blogAdmin` ← `BlogEditor.vue` 挂载时注册 `() => saveDraft(true)`，卸载时注销（**解决草稿未保存**）。
- `toolbox` / `blogFront` / `books` ← 直接接已有的 `flushToolboxPrefs()` / `flushBlogFrontPrefs()` / `flushBooksPrefs()`。
- `nav` / `smart` ← `navPrefs.flushNow()`（含 400ms 防抖的强制落盘）。
- 其余模块 store 为即时写盘，注册表为空即"天然已快照"。

`Promise.allSettled` 保证任何一个 flush 抛错都只记日志，不阻断后续上传。

## 六、作用域隔离（需求 2）

### 6.1 WebDAV 渠道（信封子集过滤）

给现有 `pushNow` / `pullNow` 增加**信封名过滤**参数，只处理命中项：

```ts
// 现有：async function pushNow(silent, skipRemoteGuard, onlyChanged)
async function pushNow(silent, skipRemoteGuard, onlyChanged, envelopes?: string[])
async function pullNow(silent, envelopes?: string[])
// 内部：const list = envelopes ? FILE_CONFIGS.filter(c => envelopes.includes(c.name)) : FILE_CONFIGS
```

对外暴露 `pushModule(moduleKey)` / `pullModule(moduleKey)`，内部查映射表转成信封名数组。
→ 进入学生工作台只 `GET student.json`；离开个人工作台只 `PUT workbench.json`；其它信封**完全不碰**。

### 6.2 飞书渠道（行级过滤，且禁止跨模块删除）

飞书是单表行镜像，`store#key` 为行键。模块作用域 = 该模块映射到的 IDB store 集合 + `nav` 里属于该模块的 key 白名单：

```ts
feishuPushScope(params, { stores: string[], navKeys?: string[] })
```

**关键约束**：作用域推送**只 upsert 本模块的行，绝不删除其他模块的行**（现有 `feishuPush` 会删"本地不存在的行"，全量时安全、按模块时必须关掉，否则会误删别的模块数据）。

### 6.3 与"模块间互不覆盖"的关系

只读写本模块信封 / 本模块行 ⇒ 其他模块数据在整个过程中既不被读也不被写，**物理上不可能被覆盖**。

## 七、失败重试与静默降级（需求 5）

### 7.1 错误分类与处理

| 情况 | 处理 |
|---|---|
| 网络失败 / 超时 | 捕获 → 记 `moduleSyncState` → 指数退避重试 |
| 鉴权失效（401/403、飞书 99991679/99991672） | 标记 `authFailed`，**停止自动重试**（重试无意义），静默；用户改凭据后手动重试 |
| 单信封失败 | 只影响该信封；同模块其他信封继续 |
| flush 失败 | `allSettled` 吞掉，记日志，上传仍继续（用已落盘的数据） |

### 7.2 重试策略

```ts
重试间隔 = min(5s × 2^n, 5min)，最多 4 次；之后置为 failed，等待手动/下次切换重试
```

- 每次任务包 `Promise.race([task, timeout(15s)])` 防悬挂。
- 重试任务重新入队（走同一串行队列），并**带上最新 epoch**。
- **本地数据全程保留**：上传失败本地不变；拉取失败本地不变。

### 7.3 静默原则

- 全程 `silent=true`：**无 toast、无对话框、无全屏 loading**（`ErrorMessage` 只写入状态对象不弹）。
- 错误统一 `console.error('[moduleSync]', ...)` + 状态记录，便于排查。
- 可选（默认关闭）：切换器条目上一个**被动小圆点**表示"该模块上次同步失败"，点击可手动重试——不影响可用性。

### 7.4 手动重试

暴露 `retryModule(moduleKey)`，并复用设置页既有的「立即同步」作为全量兜底。

## 八、数据保护（需求 3 + 5）

1. **先快照后上传**：flush → IDB → 导出 → 上传（见第五节）。
2. **本地退化守卫**：保留并复用 `guardLocal`（`nav.json` 站点数骤降拦截），模块推送同样生效，防止把"被清空的数据"推上云。
3. **只推变化**：复用 `PUSHED_SIG_PREFIX` 内容签名，内容没变直接跳过，减少无谓上传与覆盖风险。
4. **拉取用合并而非覆盖**：
   - 远端与本地内容 hash 相同 → noop；
   - 有差异但差异量 < 静默合并阈值 → **静默合并**（复用各信封的 `merge`）；
   - 差异过大 / 判定冲突 → **保留本地**，把冲突记入状态，**绝不弹框阻断**，等用户手动同步时用既有冲突弹框处理。
5. **外部改动检测**：离开推送前若发现云端被其他设备改过，则**放弃本次推送**并改为入队一次"拉取+合并"，避免覆盖他端数据。
6. **飞书按模块推送不删行**（见 6.2）。
7. **上传失败不影响本地**：本地永远是最新的那份。

## 十、风险与取舍

| 风险 | 应对 |
|---|---|
| 每次离开都上传 → 网络请求变多 | 防抖 600ms + 内容签名 `onlyChanged`（无变化不传）+ 仅 `cloudSyncEnabled` 时生效 |
| 与既有 1.5s 全局自动推送并发 | 共用同步锁串行化；模块任务优先 |
| `beforeEach` 里触发 flush 是否算"阻塞" | 不 `await`，导航立即放行；flush 通常毫秒级 IDB 写 |
| 飞书渠道按模块删行会误删 | 作用域推送关闭删除，只 upsert |
| 快速连切导致脏覆盖 | 防抖 + 串行队列 + epoch 三重保险 |
| 静默失败用户无感知 | 状态对象留痕；可选小圆点；手动「立即同步」兜底 |

## 十二、验收标准

1. 切到学生工作台时，网络请求**只出现 `student.json`**；离开个人工作台时**只出现 `workbench.json`**。
2. 切换动画与首屏渲染**无等待、无弹窗、无 loading**。
3. 博客后台编辑中（未保存草稿）切走，草稿**不丢失**且被上传。
4. 断网时切换正常，控制台有 `[moduleSync]` 错误日志，本地数据完好，恢复网络后重试成功。
5. 连打 Alt+1/2/3 快速切换，无并发请求、无数据错乱。
