# 家谱 · 取名记录标签页 功能需求

> 项目：easy-web-tab · 在「个人工作台 → 家谱」模块内**新增第三个标签页「取名记录」**
> 版本：v1.0（首版） · 文档状态：待确认，作为实现依据
> 一句话定位：**在家族档案里，把为子孙新取的名字连同寓意、性别、取名日期一并沉淀下来，便于查阅、复用与传承。**

---

## 1. 背景与目标

### 1.1 问题

在「家谱」模块里，现有的两个标签页（成员管理、家谱树）聚焦于**已存在的家庭成员与血缘关系**。但实际使用中存在一类高频却无处安放的记录需求：

| 痛点 | 具体表现 |
|---|---|
| **取名散落** | 为新生儿 / 晚辈斟酌出的名字、备选名、备选寓意，写在备忘录、聊天记录或纸上，事后难找回 |
| **寓意易忘** | 当时想好的字义、出处（诗词 / 典故 / 五行），时间一长连自己都记不清为什么取这个字 |
| **与成员割裂** | 名字最终给了哪个孩子，没有和家谱成员关联，复用与传承时缺上下文 |
| **重复劳动** | 同族同辈按字辈取名，每次都要重新回忆字辈与可用字，没有统一记录 |

### 1.2 目标

1. **一处沉淀**：把"名字 + 寓意/出处 + 适用性别 + 取名日期 + 备注"作为一个结构化记录统一入库。
2. **与家谱联动**：记录可关联到家谱成员（谁取了这个名 / 这个名给了谁），让名字不脱离家族上下文。
3. **易查阅**：列表 + 卡片双视图、关键字搜索、按性别与日期排序，三秒找到任意一条取名记录。
4. **易复用**：导出 / 导入（JSON 信封），便于在多设备间或家人间迁移与备份。

### 1.3 非目标（首版不做）

- 不做"自动起名 / 姓名打分 / 五行生克计算"等生成类能力（本标签页只负责**记录与管理**，不负责生成）。
- 不做多人协作 / 权限 / 评论。
- 不把"取名记录"提升为独立一级模块，仍作为家谱模块内的一个标签页。

## 2. 用户与场景

**主要用户**：本人（家谱维护者 / 长辈），兼顾其他参与取名的家人。

| 场景 | 用户故事 |
|---|---|
| S1 记录 | 作为长辈，我想把刚为孙子定下的名字、它的寓意和取名当天日期记下来，以免日后遗忘 |
| S2 查阅 | 作为家谱维护者，我想按"适用性别=女"或"取名日期在今年"快速筛出相关记录 |
| S3 关联 | 作为长辈，我想把某条取名记录关联到具体家庭成员（"这个名字最终给了小孙女"） |
| S4 复用 | 作为家谱维护者，我想把同一字辈的几条取名记录导出，发给同辈家人参考 |
| S5 迁移 | 作为用户，换设备后导入备份，取名记录随家谱一起完整恢复 |

## 3. 信息架构与入口位置

### 3.1 入口位置

- **归属**：个人工作台（WorkbenchView）→「家谱」模块（`WorkbenchGenealogy.vue`）。
- **位置**：家谱模块顶部 Tab 栏的**第三项**，紧随现有「成员管理」「家谱树」之后。
- **Tab 标识**（建议）：
  - 显示名：**取名记录**
  - 内部 `TabKey`：`names`（与现有 `members` / `tree` 并列，新增 `'members' | 'tree' | 'names'` 联合类型）
- **可见性**：作为家谱模块的内置标签页，默认显示；不单独做开关（若后续需要，可纳入「设置 → 家谱模块」统一显隐，本版不要求）。

```
家谱 /genealogy（个人工作台内）
├── 成员管理（members）  —— 现有：成员增删改查 + 关系 + 导入导出
├── 家谱树（tree）       —— 现有：思维导图 + 人口统计
└── 取名记录（names）    —— 新增：名字记录增删改查 + 关联成员 + 导入导出  ★
```

> 设计提示：新增标签只需在 `.fg-tabs` 中追加第三个 `fg-tab` 按钮，并在 `<template>` 中追加 `v-else-if="activeTab === 'names'"` 的内容块；复用现有工具栏、双视图、分页、弹框等成熟组件，保持一致观感。

### 3.2 页面布局（与现有家谱标签页一致）

- 顶部：`.fg-tabs` 三标签切换。
- 内容区：沿用现有 `ewt-table-toolbar`（左侧「＋ 新增」+ 搜索框；右侧视图切换），下方 `.fg-table-wrap` 承载列表 / 卡片，底部 `.ewt-pager` 分页。
- 弹框：`el-dialog` `width="80%"`，与成员新增/编辑弹框同款尺寸与栅格。

## 4. 数据模型

### 4.1 取名记录 FamilyNameRecord

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✓ | `nm_<timestamp>_<rand>` |
| name | string | ✓ | 名字（可为单字、双字或全名），≤50 字，库内**不强制唯一**（同名不同寓意属正常，见 §6 校验） |
| gender | `'male' \| 'female' \| ''` | | 适用性别；`''` 表示"通用 / 不限"，缺省 `''` |
| meaning | string | | **寓意 / 出处**：一字多义的字解、诗词典故出处、五行/字辈说明等，≤500 字（见 §4.2 说明） |
| namingDate | string \| null | | 取名日期，`YYYY-MM-DD`；缺省 `null`（未记日期） |
| memberId | string \| null | | **关联成员**（选填）：指向 `FamilyMember.id`；关联后展示成员姓名，删除成员时置空（不级联删除本记录） |
| note | string | | 备注（选填），≤500 字 |
| createdAt / updatedAt | number | ✓ | 创建 / 更新时间戳 |

> 与现有 `FamilyMember` 对齐：`gender` 复用同一 `'male'|'female'|''` 类型，展示沿用 `GENDER_LABEL = { male:'男', female:'女', '':'通用' }`（"未知"在取名语境下改为"通用/不限"更贴切，具体文案以实现时确认为准）。

### 4.2 关于「寓意或出处」字段

需求原文为「寓意或出处」。为避免拆成两个各半的字段、又保留两类信息的灵活性，**首版合并为单一自由文本字段 `meaning`**，录入时由用户自行填写"寓意"或"出处"或两者兼有（例如：`出自《诗经》"维鹊有巢"，取"巢"安家立业之意`）。

- **待确认点**：是否需要拆为 `meaning`（寓意）与 `source`（出处）两个字段？当前按"单字段、自由文本"设计，若后续统计/检索需要拆分再迭代。

### 4.3 关联成员字段

- `memberId` 为**选填**。提供下拉选择家谱中已存在的成员；下拉候选为全部成员（按姓名搜索）。
- 解除关联 / 成员被删除时，`memberId` 置 `null`，记录本身保留。
- **待确认点**：是否允许一条记录关联多个成员（同一名字给了多个孩子）？首版按"单关联"设计，如需多关联改为 `memberIds: string[]`。

### 5.3 导入导出（FR-3）

| 编号 | 需求 | 优先级 |

## 6. 数据校验要求

| 字段 | 规则 | 违反处理 |
|---|---|---|
| **name（名字）** | 必填；去除首尾空格后长度 1–50；不得仅为空白 | 提交拦截，字段下方红字 + 首个错误 toast「名字不能为空 / 不能超过 50 字」 |
| **gender（适用性别）** | 枚举 `'male'|'female'|''`，由下拉限定，不手输 | 下拉兜底为 `''`（通用），无非法值 |
| **meaning（寓意/出处）** | 选填；若填写，长度 ≤500 | 超长截断并提示，不直接报错阻断 |
| **namingDate（取名日期）** | 选填；若填写须为合法日期且 `YYYY-MM-DD`；**不应晚于今天**（取名是过去/当日动作） | 选未来日期时拦截并提示「取名日期不能晚于今天」 |
| **memberId（关联成员）** | 选填；必须是库中存在的 `FamilyMember.id`；关联成员被删除后本字段置空 | 选择时仅展示有效成员；脏引用在加载时清理为 `null` |
| **note（备注）** | 选填；长度 ≤500 | 超长截断并提示 |
| **同名** | **不拦截**：允许存在多条同名记录（不同寓意/性别/日期属正常） | —— |
| **通用健壮性** | 解析失败降级为空列表；存储不可用降级内存态并提示，不阻断页面 | 见 §8 |

> 一致性约束：名字的 1–50 字上限与现有「成员姓名」`maxlength="50"` 保持一致；性别枚举与 `FamilyMember.gender` 完全一致。

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| **一致性** | 复用项目既有组件与规范：Element Plus 控件、`ewt-table`/`RecordsCard`/`ViewModeToggle`、`CSS 变量`、`html.dark` 暗色、`44px` 移动端触控、`toast` 单例、`showConfirm` 二次确认 |
| **性能** | 单库 ≤500 条时列表筛选/搜索无感（纯函数 + `computed`）；不引入额外依赖 |
| **可测性** | 归一化 / 过滤 / 校验抽为**零 vue、零 pinia** 的纯函数（`namingCore.ts`），纳入 `node --experimental-strip-types` 测试 |
| **健壮性** | 存储不可用降级内存态；导入非法文件给出具体原因（非 JSON / kind 不符 / 结构错） |
| **无障碍** | 按钮可键盘聚焦，图标按钮带 `title`/`aria-label`，弹框支持 Esc 关闭 |

## 8. 异常与边界

| 场景 | 处理 |
|---|---|
| 名字为空 / 超 50 字 | 提交时拦截，字段下方红字 + 首个错误 toast |
| 取名日期为未来 | 拦截并提示「取名日期不能晚于今天」 |
| 寓意 / 备注超 500 字 | 保存时截断并提示（避免单条撑爆存储） |
| 关联成员已被删除 | 加载时清理脏引用为 `null`，记录保留 |
| 导入文件非 JSON / 结构错 / kind 不符 | 终止并 toast 具体原因，不留半成品 |
| 存储写入失败 | toast 提示「本地保存失败」，内存态仍可用 |
| 列表无数据 / 搜索无结果 | 空态引导「新增」或「清除搜索」 |

## 9. 关键交互流程

### 9.1 新增取名记录

```
点「＋ 新增」 → el-dialog(width=80%) 表单
  → 填 名字* / 性别 / 寓意·出处 / 取名日期 / 关联成员 / 备注
  → 点「添加」 → 校验（名字必填、日期不超前） → 落库 + markDirty
  → toast「已新增」 → 列表回到第 1 页、刷新
```

### 9.2 编辑 / 删除

```
列表行点击 / 「编辑」 → 弹框回填原值 → 修改 → 保存 → updatedAt=now → toast「已保存」
列表「删除」 → showConfirm（含名字） → 确认 → 落库 → toast「已删除」
```

### 9.3 关联成员

```
编辑弹框内「关联成员」下拉 → 选家谱成员 → 保存 → 列表"关联成员"列展示该成员姓名
（成员被删 → 该列回落「—」，记录不删）
```

## 12. 术语

- **取名记录（Name Record）**：家谱内一条"为某人新取的名字 + 寓意/出处 + 性别 + 日期"的结构化档案。
- **关联成员**：取值记录与家谱 `FamilyMember` 的引用，用于把"名字"绑定到具体家族成员。
- **信封（Envelope）**：导入导出文件的外层结构（`kind/version/exportedAt/items`），与现有家谱/智能工作台保持一致约定。

## 13. 待确认项（实现前需拍板）

1. **Tab 显示名**：「取名记录」是否合适？或改「起名记录」「名字档案」？
2. **性别文案**：`''` 在取名语境下显示「通用 / 不限」还是沿用家谱的「未知」？
3. **寓意/出处**：单字段自由文本，还是拆为 `meaning` + `source` 两字段？
4. **关联成员**：单关联（`memberId`）还是多关联（`memberIds`）？
5. **导入导出**：首版是否纳入（影响 FR-3 优先级）？
