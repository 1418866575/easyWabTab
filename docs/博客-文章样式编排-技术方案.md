# 博客文章样式编排（排版主题）— 技术方案

> 状态：**设计稿，未实施**。
> 参考对象：`https://www.zhaotab.com/typeset`（公众号排版工具：左 Markdown、右实时预览、35 套主题、一键复制带样式正文、字号比例预览、分割线样式随主题变化）。
> 目标：把「写文章」的排版从**写死的一套**升级为**可选主题 + 单篇微调**，编辑器预览 / 博客前台 / 公众号三端观感一致。

---

## 1. 现状链路（改造基线）

```
contentMarkdown
   │
   ├─ renderMarkdown()  noteMarkdown.ts   markdown-it html:false + breaks:true
   │                    自定义：==高亮== → <mark>；任务列表 → ☐/☑ 文字符号
   │
   ├─→ 编辑器预览   BlogEditor.vue:481  publishedHtml → .be-preview.md-body  (v-html)
   ├─→ 博客前台     BlogPostView.vue:52 → .bf-post-body.md-body               (v-html)
   ├─→ 静态导出     blogStaticExport.ts:167 同源 renderMarkdown 内联进静态页
   └─→ 公众号       buildWechatContentHtml (useWechatPublish.ts:364)
                      DOMParser → normalizeWechatBody(root)
                        ├ flattenLists   列表摊平成 <section>（公众号不认 ul/li）
                        ├ flattenTables  表格摊成卡片（公众号列宽不可靠）
                        ├ convertMarks   <mark> → 浅黄底 <span>（公众号不认 mark）
                        └ applyInlineStyles → styleFor(tag)  ★★ 写死的一套浅色主题
```

**关键事实：样式已经有一个「编排点」，只是不可配置。**

- `useWechatPublish.ts:95-144` 的 `styleFor(tag, el)`：h1-h6 / p / a / code / pre / blockquote / hr / table / th / td / img 全部写死色值（`#1f1f1f`、`#576b95`、`#f6f8fa`、`#d9d9d9`…）与尺寸。
- `markdown.css` 的 `.md-body`：前台与预览共用，全走 `--color-*` Design Token，明暗自适应。
- 也就是说：**同一个 Markdown 在公众号里永远是一套浅色样式，在博客前台永远是另一套 token 样式**，两套互不相干、都改不了。

### 必须遵守的既有限制（不可绕过）

| 限制 | 出处 | 影响 |
|---|---|---|
| 公众号**不支持 class / id / 伪元素**，只认 `style` 内联 | `applyInlineStyles` 里 `el.removeAttribute('class')` | 主题在公众号端必须展开成内联样式，装饰性内容必须落成真实 DOM 节点 |
| 公众号不认 `<mark>`、`<ul>/<li>`、`<table>` | `normalizeWechatBody` 顺序有讲究：先摊平列表 → 卡片化表格 → 转 mark → 内联 | 新增的主题处理必须插在这条链的**正确位置**，不能打乱顺序 |
| markdown.css 是**全局共享**（WorkbenchDiary 也用） | `src/main.ts:17` | 改 `.md-body` 必须 100% 带 fallback，默认值与现值逐条相等，否则日记/便签跟着变 |
| `html:false`，`<svg>` 图片被禁 | `noteMarkdown.ts` | 主题不能靠用户手写 HTML 实现 |

## 2. 方案总览

一句话：**主题 = 一组 `--t-*` 排版 Token**。定义一次，三个消费端各自消费：

```
                 ┌─ BlogTypoTheme（预设 10 套，手工 token 包）
                 │
typo（单篇微调）─┤
                 │
   blogTypoCore.ts  ← 唯一的纯逻辑源：解析 / 合并 / 生成
                 │
   ┌─────────────┼──────────────────┐
   │             │                  │
   ▼             ▼                  ▼
typoStyleVars()  .md-body 读        styleFor(tag, tokens)
返回 style 对象   --t-* 变量         公众号内联样式
（CSS 变量注入）  （CSS 伪元素装饰）  （无伪元素 → DOM 级装饰）
   │             │                  │
编辑器预览      博客前台            公众号复制 / 草稿箱
```

### 核心锚点：默认主题 = 「跟随系统」，不注入任何变量

`--t-*` 的 fallback 全部写成 `.md-body` 的现值。只要没有显式主题（老文章、日记、便签、
`typo.themeId` 为空），渲染结果与今天**逐字节一致** —— 这是整个方案不引入回归的保证，
也是为什么 `.md-body` 改造是安全的。

## 3. 数据结构

### 3.1 Token 表（`--t-*`，共 18 个）

| Token | 含义 | fallback（= 现状，改 CSS 时逐条照抄） |
|---|---|---|
| `--t-font` | 正文字体栈 | `inherit` |
| `--t-font-size` | 正文字号 | `var(--font-size-sm, 14px)` |
| `--t-line-height` | 行高 | `var(--line-height-relaxed, 1.75)` |
| `--t-paragraph-gap` | 段落间距 | `0.6em` |
| `--t-heading-gap` | 标题上下距 | `0.8em 0 0.4em` |
| `--t-text` | 正文色 | `var(--color-text, #0f172a)` |
| `--t-heading` | 标题色 | `var(--color-text, #0f172a)` |
| `--t-heading-weight` | 标题字重 | `700` |
| `--t-accent` | 主题色（链接 / 引用竖线 / 强调） | `var(--color-primary, #3b82f6)` |
| `--t-link` | 链接色 | 同上 |
| `--t-quote-bg` | 引用块底色 | `transparent` |
| `--t-quote-border` | 引用竖线色 | `color-mix(currentColor 35%)` |
| `--t-quote-text` | 引用文字色 | `color-mix(currentColor 78%)` |
| `--t-code-bg` | 行内代码底色 | `color-mix(currentColor 12%)` |
| `--t-code-color` | 行内代码字色 | `currentColor` |
| `--t-pre-bg` | 代码块底色 | `color-mix(currentColor 12%)` |
| `--t-img-radius` | 图片圆角 | `var(--radius-md, 8px)` |
| `--t-hr-style` | 分割线样式 | `line` \| `dots` \| `dashed`（默认 `line`） |

> 表格边框色沿用 `--t-accent` 的弱化版（`color-mix(accent 22%, transparent)`），
> 不单独开 token，避免变量表继续膨胀。

### 3.2 类型定义（`src/types/index.ts`）

```ts
/** 单篇文章的排版：引用预设主题 + 三个微调项 */
export interface BlogTypo {
  /** 预设主题 id；空串 = 跟随全局默认（settings.defaultTypoId，再空 = 跟随系统） */
  themeId: string
  /** 正文字号 px，14-20；undefined = 用主题值 */
  fontSize?: number
  /** 行高 1.5-2.2；undefined = 用主题值 */
  lineHeight?: number
  /** 段距 em，0.4-2；undefined = 用主题值 */
  paragraphGap?: number
}
```

- `BlogArticle.typo?: BlogTypo` —— 老文章无此字段 = 默认主题，无需迁移。
- `BlogSettings.defaultTypoId?: string` —— 全局默认（博客设置里选），缺省 = 跟随系统。

### 3.3 纯逻辑模块 `src/composables/blogTypoCore.ts`（新增）

```ts
export interface TypoTheme {
  id: string            // 't_follow' | 't_classic' | ...
  name: string
  desc: string
  /** 弹框顶部分类药丸的分组：'color' 彩色 | 'simple' 简约 | 'wechat' 公众号 */
  group: 'color' | 'simple' | 'wechat'
  /** 预览卡片上的主色圆点（纯展示） */
  swatch: string
  tokens: Record<string, string>
  /** 暗色覆盖（仅前台/预览消费；公众号固定浅色） */
  dark?: Record<string, string>
}

export const TYPO_THEMES: TypoTheme[]
export function resolveTypo(typo: BlogTypo | undefined, defaultId?: string): TypoTheme
export function typoVars(typo: BlogTypo | undefined, defaultId?: string, dark?: boolean): Record<string, string>
export function typoInlineStyle(tag: string, tokens: Record<string, string>): string
```

- `resolveTypo`：非法 / 不存在的 `themeId` 一律回落「跟随系统」，**不抛错**（项目惯例：降级不抛错）。
- `typoVars`：把选中主题的 tokens 与三个微调项合成最终的 `--t-*` 映射；返回 `{}` 表示跟随系统。
- `typoInlineStyle`：公众号端的唯一出口，`tag → style` 字符串；默认主题输出**必须与现
  `styleFor()` 逐字节一致**（见 §8 回归测试）。

## 4. 预设主题（首期 10 套）

主色取自项目 9 色 palette 的 600 级，保证与全站观感协调。

| id | 名称 | 特征 | 主色 |
|---|---|---|---|
| `t_follow` | 跟随系统 | 不注入任何 token（= 现状） | — |
| `t_classic` | 经典公众号 | 16px / 1.75 / `#3f3f3f` / 链接微信蓝 | `#576b95` |
| `t_teal` | 青提 | 绿调标题 + 浅绿引用底 | `#0F6E56` |
| `t_coral` | 蜜橙 | 橙调、行高 1.8 | `#993C1D` |
| `t_blue` | 藏蓝 | 蓝调标题、引用左竖线 | `#185FA5` |
| `t_pink` | 粉笺 | 粉调、引用浅粉底 | `#993556` |
| `t_purple` | 紫烟 | 紫调 | `#534AB7` |
| `t_ink` | 墨纸 | 黑字白底、衬线标题、无装饰 | `#1f1f1f` |
| `t_paper` | 暖纸 | 暖灰字 `#3d3a37`、代码块浅米底 | `#854F0B` |
| `t_large` | 极简大字 | 17px / 行高 2.0 / 段距 1.4em（手机阅读友好） | `#444441` |

`dark` 覆盖只调 `--t-text / --t-heading / --t-code-* / --t-quote-*` 四组底色与字色，
背景仍由页面控制，主题不碰。

> 分组（只服务弹框筛选药丸，不参与存储）：**彩色** = 青提/蜜橙/藏蓝/粉笺/紫烟/暖纸，
> **简约** = 跟随系统/墨纸/极简大字，**公众号** = 经典公众号。
> 参考站的 35 套属于内容量而非架构问题；**「随机换」已明确裁掉，不做。**

## 6. 三端接入细节

### 6.1 编辑器预览（`BlogEditor.vue`）

```html
<div class="be-preview md-body" :style="typoStyle" v-html="publishedHtml" />
```

`typoStyle = computed(() => typoVars(form.typo, store.settings.defaultTypoId))`。
预览即所得：主题切换、滑杆拖动立即反映，无需点保存。

### 6.4 主题选择弹框（`BlogTypoDialog.vue`）

参考 `zhaotab.com/typeset` 的选择器形态，壳走 `BaseDialog`（宽 `min(760px, 92vw)`）：

```
┌ 选择排版主题                     ● 青提 ┐   ← 顶栏：当前主题色点 + 名称（无随机换）
│ [全部 10] [彩色 6] [简约 3] [公众号 1]  │   ← 分类药丸（TypoTheme.group 统计）
│ ┌────────┐ ┌────────┐ ┌────────┐      │
│ │小标题样式│ │小标题样式│ │小标题样式│      │   ← 每张卡 = 该主题 token 渲染的
│ │正文…重点…│ │正文…重点…│ │正文…重点…│      │     迷你示例（非截图，主题扩充自动生成）
│ │▎引用长这样│ │▎引用长这样│ │▎引用长这样│      │
│ │● 青提 设默认│ │● 蜜橙 设默认│ │● 藏蓝…│      │   ← 卡脚：色点 + 名称 + 设默认
│ └────────┘ └────────┘ └────────┘      │
│ 点卡片应用到本篇；「设默认」改全站默认    完成 │
└───────────────────────────────────────┘
```

交互语义（两个角标可落在不同主题上）：

| 动作 | 作用域 | 落库 |
|---|---|---|
| 点卡片 | 应用到**本篇**（`article.typo.themeId`，蓝描边 + 「本篇」角标） | 随文章保存 |
| 点「设默认」 | 改**全站默认**（`settings.defaultTypoId`，卡片脚显示「默认」角标） | `updateSettings`，走既有 settings 合并 |
| 再点一次「已默认」 | 恢复为 `t_classic`（避免默认主题悬空） | 同上 |

迷你示例卡实现：卡片容器 `style.setProperty(k, tokens[k])` 注入变量后渲染固定三行
示例 HTML（`h4` + `p>strong` + `blockquote`），字号固定 11-12px 只比结构不比尺寸。
主题扩到 35 套时卡片零成本自动生成。

编辑器右栏只保留一行入口（当前主题 + 「换主题」）+ 微调滑杆，不再平铺主题列表。

### 6.2 博客前台（`BlogPostView.vue`）

同款注入，`dark` 由 `document.documentElement.classList.contains('dark')` 决定是否取
`theme.dark`。共享 / 静态导出走同一 token 集，写入静态页 `<style>`。

### 6.3 公众号（`useWechatPublish.ts`）

处理链保持现有顺序，只做两处替换：

```
flattenLists → flattenTables → convertMarks → decorateHr(新增) → applyInlineStyles(tokens)
```

- `applyInlineStyles` 内部从 `styleFor(tag)` 换成 `typoInlineStyle(tag, tokens)`，
  语义不变：仍然是「按标签查一张表」。
- `decorateHr`：公众号不支持伪元素，`--t-hr-style: dots` 时把 `<hr>` 替换成
  `<section style="text-align:center;...">●&nbsp;●&nbsp;●</section>`；
  `dashed` 用 `border-top:1px dashed`。`line` 走原内联。
- 标题装饰（色条、圆点前缀）**不在 P0**：公众号端要包真实 DOM span，且 10 套主题 ×
  6 级标题的组合会爆炸。P0 标题只做「颜色 / 字号 / 字重」，与 token 一一对应。

## 7. 已知的坑（实施时逐条核对）

| # | 坑 | 后果 |
|---|---|---|
| 1 | `normalizeArticle`（`blogCore.ts:190-215`）是**逐字段重建**，与 `normalizeImage` 同型。漏带 `typo` 会导致云同步 / IDB 往返后主题静默丢失 | 老问题复发（同 tombstone `keepStamp`、图片 `updatedAt` 教训） |
| 2 | `.md-body` 被 WorkbenchDiary 共用 | fallback 与现值差 1px 就会波及日记排版；改完必须并排截图对比 |
| 3 | `blogShare.ts:122` 前台文章合并用 `updatedAt` 比较，`typo` 属于文章字段 | 主题变更必须推进文章 `updatedAt`（现有 `updateArticle` 已统一处理，不要绕开它直改） |
| 4 | 公众号 `styleFor` 的 `pre` 带 `white-space:pre-wrap` 等特殊处理 | 重构成查表时不能丢；`code in pre` 与行内 `code` 是两个分支 |
| 5 | `--t-hr-style` 的 `dots` 在公众号端是 DOM 替换 | 必须放在 `applyInlineStyles` **之前**，否则 `<section>` 没机会被内联 |
| 6 | 主题 tokens 缺键 | `typoVars` 输出时缺键即等于 fallback → 该属性回落系统样式，**不要**用空串覆盖 |
| 7 | `BlogTypo` 三个微调项的 clamp | 放 `blogTypoCore`，非法值（NaN / 越界）一律丢弃（`undefined`），不在 UI 层拦 |

## 8. 测试计划

新增 `scripts/test-blog-typo.ts`（`npm run test:blog-typo`，纯逻辑、零 DOM）：

1. `resolveTypo`：合法 id / 非法 id / undefined / 空串 → 全部回落；`defaultId` 优先级正确。
2. `typoVars`：微调项覆盖主题值；越界与 NaN 丢弃；跟随系统返回 `{}`。
3. `typoInlineStyle`：**默认（classic）主题对每个 tag 的输出，与现 `styleFor()` 硬编码逐字节相等**
   —— 这是防回归的锚点测试，直接把 `useWechatPublish.ts` 现字符串抄进断言。
4. 每套预设主题 token 完整性：必需键不缺、颜色值合法（`/^#[0-9a-f]{6}$/i` 或合法 CSS）。
5. `decorateHr` 三种样式的 DOM 断言（jsdom-free：直接传伪造 document 会引入依赖，改为把
   HR 样式生成独立成 `hrMarkup(tokens): string` 纯函数测字符串）。

`test-blog-core.ts` 追加：`normalizeArticle` 保留 `typo`；缺失时不出键。

**人工验证**（构建过不了的部分）：
- 编辑器切 10 套主题预览逐套目视；
- 前台明 / 暗两态各截一次；
- 日记本、便签预览（确认未受波及）；
- 公众号草稿箱发一篇（classic 主题应与改造前观感一致）。

## 10. 明确不做（本期边界）

- 不做「富文本编辑器」——输入仍是 Markdown，样式编排只作用于**渲染结果**。
- 不做每段 / 每字的行内样式定制（那等于换编辑器）。
- 不做主题的在线自定义编辑器（改主题 = 改代码里的 token 包）。
- 不动公众号已验证的列表摊平 / 表格卡片化逻辑，只替换其中的取色来源。
- 不支持用户上传自定义字体文件（版权与体积）。
