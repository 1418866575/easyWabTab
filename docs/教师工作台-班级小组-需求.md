# 教师工作台 · 班级小组 —— 需求说明（v1）

## 1. 背景与目标

教师工作台已有学生信息、座位表、值日、点名、成绩、试卷、家长联系、奖励、请假、作业、家校谈话等模块，
但**「把学生分成不同的组」这件事始终散落在各个模块、且能力很弱**：值日生表（duty）只是按名单轮流自动排，
点名（random）只能随机抽一个人，没有任何一处能让教师「维护一组可复用/可临时生成的学习小组」。

日常教学中分组需求非常高频且多样：长期的固定学习小组、活动时的临时分组、随机分组、按性别分组……
目前教师只能临时在纸上或微信群里手动排，费时且无法沉淀、无法复用、无法打印发给家长。

本需求新增 **班级小组** 模块，让教师在教师工作台一个页面内完成：
**固定组/临时组的维护 → 多种策略的自动分组 → 分组快照保存与复用 → 导出/打印**。

## 2. 归属与权限

| 约束 | 说明 |
|---|---|
| **归属班级** | 数据挂在 `ClassBucket`（`groups[学期][班级]`）下，与值日、奖励、请假同层，**随学期×班级隔离**；换学期/换班数据互不可见 |
| **可见性（待确认）** | 推荐 **不进 `TEACHER_HEAD_ONLY_PAGES`**（班主任、科任都可见）——活动分组科任也常用；若你坚持仅班主任可用，则并入 head-only 与座位表同级 |
| **数据归属** | 走 IndexedDB `teacher_workbench` 单对象，云同步 `teacher.json` 信封；成员只存 `studentId`（主键），不存姓名，规避重名 |

## 3. 分组场景梳理（含补充场景）

你提到的场景：长期固定学习分组、活动临时分组、随机分组、按性别各自分组。
结合一线教学实际，补充如下场景（作为功能设计的输入）：

### 3.1 按「组的生命周期」分
- **长期固定学习小组**：跨整学期/整学年复用，如 6 人学习小组，用于日常合作、收作业、互评。
- **临时活动分组**：一次性活动用，用完即弃或可存为快照日后复用（如公开课、社会实践、游戏）。
- **分组快照/历史**：把某次生成的分组结果保存下来，日后「一键应用」成新的临时组，避免重复排。

### 3.2 按「分组策略」分
- **纯随机分组**：指定组数或每组人数，洗牌后均分。
- **按性别各自分组**：男一组 / 女一组；或男女各自独立随机（如男生分 3 组、女生分 2 组）。
- **按成绩/能力分层**：
  - *同质*：水平相当的学生同组（便于分层教学）；
  - *异质*：每组高/中/低均衡（便于互助）。
  - 注：`Student` 模型**无成绩字段**，成绩需从 `exams` 聚合平均分；若本班无成绩数据则该策略降级/禁用。
- **按学号/座位顺序分组**：顺序切块（1–6 组 A，7–12 组 B…）或蛇形（避免始终同一批人同组）。
- **按兴趣/特长/社团分组**：基于学生标签（现有模型暂无该字段，列为后续扩展，本期可用「备注/职务」近似）。
- **异质均衡分组**：综合「性别 + 成绩」让每组男女比例与水平都尽量均衡（最常用的公开课/活动分组）。
- **按住校/走读分组**：`Student.boarding` 字段可直接分桶（住校生/走读生各自成组或均衡）。
- **抽签/抓阄分组**：随机但过程可公示（洗牌动画/结果可复现），增强公平感。

### 3.3 按「约束条件」分
- **锁定同组**：某些学生必须同组（如好友、需要互助的强弱搭配）。
- **隔离不同组**：某些学生不能同组（如矛盾双方、避免抱团）。
- **指定每组人数 vs 指定组数**：两种入口，满足不同活动。
- **人数不能整除的余数处理**：轮转补位 / 最小组吸收 / 随机补位，三种策略可配。
- **小组角色分配**：每组设组长、记录员等角色（存 `studentId → 角色`）。

### 3.4 与其他模块的联动（机会点，非本期强依赖）
- 与**学生名单**联动：选人入组直接复用花名册（需新做学生多选选择器，现有列表无勾选）。
- 与**点名(random)**联动：可一键把某组作为抽人范围。
- 与**值日(duty)**联动：值日本就是「按名单轮流」，可复用分组结果。
- 与**座位(seats)**联动：分组结果可映射成座位布局（后续扩展）。

### 3.5 输出
- **导出/打印**：分组结果导出为文本/Markdown（每组一行名单），或打印贴墙/发家长。

## 4. 功能需求（FR）

### 4.1 小组的增删改查
- FR1.1 新建小组：填组名、类型（固定/临时）、描述、添加成员。
- FR1.2 编辑小组：改全部字段、加减成员、设角色。
- FR1.3 删除小组：二次确认。
- FR1.4 复制为临时组：把固定组快速复制成一份临时组再调整。
- FR1.5 列表 + 卡片双视图（复用 `useViewMode` + `ewt-card-grid` + `ewt-table`）。

### 4.2 成员管理
- FR2.1 多选学生入组（新做学生多选选择器：来源 `sortedStudents`，展示用 `tw-chip`，按性别着色）。
- FR2.2 移除成员、拖拽/点击调整。
- FR2.3 设小组角色（组长/记录员等，可选）。
- FR2.4 成员以 `studentId` 存储，展示时反查 `Student`（姓名/性别/学号）。

### 4.3 自动分组引擎
- FR3.1 策略：随机 / 按性别 / 按成绩（同质·异质）/ 按学号顺序（切块·蛇形）/ 异质均衡 / 按住校。
- FR3.2 参数：指定组数 或 指定每组人数（二选一）。
- FR3.3 约束：锁定同组（`string[][]`）、隔离不同组（`string[][]`）。
- FR3.4 余数策略：轮转补位 / 最小组吸收 / 随机补位。
- FR3.5 按性别分（genderSplit）：开启后男女各自独立分组。
- FR3.6 实时预览分组结果，可「保存为临时组」或「存为快照」。
- FR3.7 无解检测：锁组与隔离冲突、组数 > 学生数等给出明确提示。

### 4.4 快照与复用
- FR4.1 保存当前分组结果为快照（命名、时间）。
- FR4.2 快照列表（双视图），一键应用为临时组。
- FR4.3 删除/重命名快照。

### 4.5 导出与打印
- FR5.1 导出分组结果为 Markdown/纯文本（每组：组名 + 成员名单）。
- FR5.2 打印视图：隐藏非必要元素（`tw-no-print`），适配 `@media print`。

### 4.6 数据一致性与持久化
- FR6.1 持久化到 IndexedDB `teacher_workbench`，随 `teacher.json` 云同步。
- FR6.2 删除学生时级联清理其在各小组/快照中的 `studentId`（扩展 `removeStudentCascade`）。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| UI 一致性 | 复用现有 `ewt-*` / `tw-*` 范式（双视图、`.ewt-dialog-footer`、`.ewt-pager`、`usePageSize`） |
| 响应式 | 移动端（≤768px）强制卡片视图，与 `useViewMode` 行为一致 |
| 性能 | 班级人数通常 ≤ 60，纯前端分组无需虚拟化；分组算法为纯函数放 `teacherCore.ts` |
| 隐私 | 分组属班级数据，随 `teacher.json` 云同步；凭据仅本机不跨设备覆盖 |
| 可访问性 | 弹框 ESC/外部点击关闭、`role`/`aria-label` 对齐现有弹框 |

## 6. 范围与边界

**本期做**：固定组 + 临时组 CRUD、自动分组引擎（上述 6 种策略 + 约束 + 余数策略）、快照保存与复用、双视图、导出/打印、级联清理。
**暂不做（后续扩展）**：与座位表联动自动排座、分组积分/排行榜、家长端可见分组、兴趣/特长标签分组（需先扩 `Student` 模型）。

## 7. 验收标准

1. 能新建固定组和临时组，成员以 `studentId` 正确存储，列表/卡片双视图正常。
2. 随机分组：指定组数或每组人数，结果均分、可预览、可保存为临时组或快照。
3. 按性别分组 / 异质均衡分组：每组男女比例与水平符合策略预期。
4. 锁组/隔离约束生效；冲突时给出明确提示而非静默错误。
5. 删除学生后，其在所有小组/快照中的引用被级联清除，无脏数据。
6. 分组结果可导出 Markdown、可打印。
7. `vue-tsc -b` 0 类型错、`vite build` 通过；移动端卡片视图正常。
