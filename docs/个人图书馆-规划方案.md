## 1. 结论先说：这件事你已经有一半了

不需要从零设计，项目里有**两套现成骨架**可以复用，图书馆只是把它们拼起来：

| 现成资产 | 位置 | 可复用度 |
|---|---|---|
| 「放 HTML → 前台点击打开」模式 | `public/games/`（8 个自包含 `index.html` + `manifest.json`），加载逻辑 `src/stores/sites.ts` 的 `loadGames()` | **直接复用**，只需把书从 games 拆出来 |
| 阅读型前台骨架 | `/blog`（`BlogHomeView.vue` + `styles/blog-front.css`）：搜索 + 筛选 + 排序 + 分页 + 卡片网格 + 收藏/最近阅读 | **照抄结构**，换数据源即可 |
| 构建期生成脚本体例 | `scripts/generate-preset-icons.cjs`（build 前置）、`scripts/gen-toolbox-entries.cjs` | **同款写一份**扫描 books 目录 |
| 纯逻辑自测体例 | `scripts/test-blog-core.ts` + `npm run test:blog` | **同款**写 books core 测试 |
| 本地偏好单例 | `src/composables/blogFrontPrefs.ts`、`useToolboxPrefs.ts`（模块级 ref + 防抖落盘） | **同款**写 books 偏好 |
| 入口挂载 | `src/components/WorkbenchSwitcher.vue`（Alt+W 命令面板） | 加一条 entry |
| SPA 回落 | nginx `try_files $uri $uri/ /index.html` | **无需改动**，新路由直接可刷新 |

**一句话**：这是 `games/manifest.json` 的模式 + `/blog` 的界面，套在 `/books` 路由上。

**规则**（刻意简单，够用即可）：

- 每本书 = 一个子目录，目录名即 `id`（小写字母 + 连字符）。

- `meta.json` 可选。缺省时脚本用目录名 + HTML 的 `<title>` 兜底，卡片照样正常显示。

## 4. 数据契约

### 4.1 `manifest.json`（生成物）

```jsonc
[
  {
    "id": "daodejing",              // 目录名
    "title": "道德经",              // meta.json > HTML <title> > 目录名
    "description": "道可道，非常道…", // meta.json > HTML meta[description] > 空
    "cover": "/books/daodejing/cover.png", // meta.json > 有 cover 则填，否则空串走占位
    "category": "国学经典",          // meta.json > "未分类"
    "tags": ["老子", "道家"],        // meta.json > []
    "order": 10,                     // meta.json > 按目录名排序
    "entry": "/books/daodejing/index.html", // 必带
    "size": 347386,                 // 脚本统计，字节
    "updatedAt": "2026-10-13T…",    // index.html mtime
    "hasMeta": true                 // 是否存在 meta.json
  }
]
```

### 4.2 可选的 `meta.json`

```json
{
  "title": "道德经",
  "description": "道可道，非常道。名可名，非常名。",
  "cover": "cover.png",
  "category": "国学经典",
  "tags": ["老子", "道家", "春秋"],
  "order": 10
}
```

`cover` 写文件名即可（相对本目录）；不写 `title` 会自动回落到 HTML `<title>`。

### 4.3 偏好数据（IndexedDB 本地；收藏 + 用户书签进云同步）

IndexedDB `easy-web-tab` 库 `nav` store 单键 `books-prefs`（与导航站偏好同库不同键，`DB_VERSION` 已到 23）：

```jsonc
{
  "favorites": ["daodejing"],
  "recent": { "gushi": 1750000000000 },
  "clicks": { "daodejing": 12, "gushi": 3 },
  "bookmarks": { "daodejing": { "ratio": 0.42, "label": "第 21 章", "ts": 1750000000000 } },
  "userBookmarks": [{ "id": "bm_xxx", "title": "我的笔记", "content": "一段自定义内容", "ts": 1750000000000 }]
}
```

> **云同步范围（2026-10-13 定稿）**：`favorites`（收藏）+ `userBookmarks`（用户自建书签）经 `books.json` 信封走全局云同步
> （`useCloudSync.ts`，合并策略见 §14.14）；`recent` / `clicks` / `bookmarks`（阅读位置）/ 上传书为**设备级**，不进云。
> 阅读位置书签是**设备相关**的（换设备屏幕尺寸不同，ratio 位置就不对），跨设备同步反而错位 —— 这条逻辑依然成立，故阅读位置仍只存本机。

## 5. 生成脚本设计

`scripts/gen-books-manifest.cjs`，挂进 `build` 前置（与 `generate-preset-icons.cjs` 并列）：

```
node scripts/gen-books-manifest.cjs && node scripts/generate-preset-icons.cjs && vite build
```

流程：

1. 读 `public/books/` 一级子目录，跳过 `_` 前缀与 `manifest.json`
2. 每个目录找 `index.html`，找不到 → **跳过并在控制台告警**（不静默吞掉，AGENTS 铁律）
3. 读可选 `meta.json`，容错：非法 JSON 只警告不抛错，回落到兜底值
4. 缺 title 时正则抽 HTML `<title>`，仍缺则用目录名
5. 统计 index.html 字节数与 mtime
6. 合并已有 manifest 里**人工加过、脚本又覆盖不到**的字段（用 `hasMeta` 标记区分）
7. 按 `order` 升序、其次按 `title` 排序，写回 `manifest.json`

同时提供 `npm run gen:books` 手动跑，方便改完 meta.json 立刻刷新。

> **兜底铁律**（沿用博客模块的 P4/P5 规则）：脚本**绝不删条目**，只增补；`meta.json` 缺字段时回落默认值，不写入 `undefined`。

## 6. 两种打开方式

### 6.1 新标签页直开（默认）

卡片主按钮 → `window.open(entry, '_blank')`。与现有 `SiteCard.vue` 行为完全一致。

优点：你的 HTML 是 30万~60万字符的大文件，独立打开加载最快、零样式冲突。**这是主路径。**

### 6.2 站内 iframe 阅读页（可选）

路由 `/books/read/:id`，卡片次按钮进入。

- `<iframe :src="book.entry">` 占满内容区，顶部一条轻量工具栏：返回书架 / 书名 / 「新标签页打开」/ 收藏
- **能记录阅读位置**：同源静态文件，`onload` 后可访问 `contentWindow`，绑定 `scroll` 节流保存 `ratio = scrollTop / (scrollHeight - clientHeight)`
- **能恢复位置**：加载完成后 `scrollTo(0, ratio × 可滚动高度)`
- 移动端（≤768px）iframe 全屏，工具栏收成一行

> ⚠️ **已知限制（必须在界面上说清）**：新标签页模式下**无法记录阅读位置**（跨文档控制，且不保证对方 HTML 有上报脚本）。所以「书签」功能只在 iframe 模式下生效。卡片上书签入口只在有 iframe 按钮时出现。

## 7. 功能清单

### 7.1 搜索 + 分类筛选 + 排序

- 搜索：标题 / 简介 / 标签 模糊匹配，空格分词（照搬 `useBlogListing` 的 URL query 同步，筛选态可分享/刷新保持）
- 分类：从 manifest 的 `category` 去重生成，空分类自动隐藏（照搬工具箱分类页签）
- 排序：最近打开 / 打开次数 / 标题 A→Z / 更新时间
- 结果计数条 + 清空筛选
- **移动端强制卡片视图**：复用 `useViewMode()`，注意**不能解构**（`const vm = useViewMode()` 后用 `vm.isMobile`，否则永久失去响应式）

### 7.2 最近打开 + 打开次数

- 每次打开写 `recent`（去重倒序，截断 12 条）+ `clicks[id]++`
- 「最近阅读」分区置顶展示，空时自动隐藏（照搬 `BlogHomeView` 的 section 写法）
- 打开次数降序作为默认排序 —— 与工具箱 `sortByClicks` 规则一致

### 7.3 收藏星标

- 卡片右上角星标，`toggleFavorite(id)`
- 列表上方「我的收藏」分区，空时隐藏
- 排序选项加「仅看收藏」

### 7.4 阅读位置书签 ⭐

这是你额外提的需求，也是本模块最实用的一块。

| 项 | 设计 |
|---|---|
| 记录时机 | iframe 内滚动停顿 800ms 后保存 `{ ratio, label?, ts }`；`label` 默认取当前可见的首个 `h1/h2` 文本（滚动容器内查询），拿不到就留空 |
| 手动书签 | 阅读页工具栏「书签」按钮，可**手动命名**（如「第 21 章 天道」） |
| 列表展示 | 卡片底部一行「上次读到 42% · 第 21 章」，点击直接跳 `/books/read/:id` 并自动恢复 |
| 恢复 | iframe `onload` 后等 300ms（等原文档渲染完）再 `scrollTo`；连续两次没对上则放弃并提示 |
| 清除 | 阅读页「清除书签」+ 卡片长按/次级菜单 |
| 上限 | 每书 1 个书签（记录"读到哪"），不存历史列表 —— 保持简单 |

## 9. 视觉规范（照 `docs/UI_STYLE_GUIDE.md`，不自造一套）

| 元素 | 规范 |
|---|---|
| 卡片 | `.ui-card` + `--radius-lg`；阴影 `--shadow-card`，hover `--shadow-card-hover` + `--motion-hover-rise` |

| 空态 | 照搬 `.bf-empty` 写法：虚线边框 + `--color-bg-card` 底 |
| 深色模式 | 只用 token，HTML 本体是自包含文件不跟随主题（提前说明，不做适配） |
| 移动端 | 断点统一 768px，窄端媒体查询**写在基础规则之后**（同特异性后声明胜出，这个坑项目已踩过） |

## 12. 风险与对策

| 编号 | 风险 | 对策 |
|---|---|---|
| R1 | 自包含 HTML 未做校验，可能有书打不开 | 脚本校验 `index.html` 存在；可选在生成时抓 `<title>`，抓不到就说明文件异常 |
| R2 | iframe 内跨浏览器行为差异（国产浏览器内核） | 已有 `X-Frame-Options` 风险 → nginx **不要**给 `/books/` 加该头；iframe 模式失败时降级提示「请用新标签页打开」 |
| R3 | 单本 HTML 很大（60万字符），列表页不该预加载 | 列表页**只读 manifest**，绝不 fetch HTML 正文 —— 这是本方案性能的关键 |

## 14. 实施补记（2026-10-13）

初稿设计里有 **3 处被实测推翻**，都在实施时改掉了。记录在此，避免以后重蹈。

### 14.1 关键发现：书不一定靠 window 滚动

**初稿假设**：阅读位置 = 读 iframe 的 `window.scrollY`。

**实测**：道德经（`public/books/daodejing/index.html`）是侧边目录布局 ——

```
documentElement.scrollHeight = 849, clientHeight = 849   ← 文档根本滚不动
nav.toc-sidebar:  scrollHeight = 4518, clientHeight = 809  ← 正文在这
```

`window.scrollTo(0, n)` 对这类书**完全无效**。只盯 window 的实现，书签会永远是空 —— 而侧栏目录恰恰是很常见的电子书布局。

**改法**（`booksCore.pickScrollTarget` 纯函数 + 单测覆盖）：
1. 文档本身可滚 → 用 window
2. 否则在文档里找**面积最大**且确实超出视口的 `overflow-y: auto|scroll` 元素
3. 都没有（书太短滚不动）→ 不记书签，而不是记一条 0%

### 14.2 浏览器端上传（Q3）怎么做才对

初稿 §13 的 Q3 建议「首版不做」，理由是「纯前端拿不到写 public 的权限」。用户选择要做，实现如下：

| 环节 | 做法 |
|---|---|
| 存储 | IndexedDB `books` store（`DB_VERSION` 22 → **23**），按 id 多记录 |
| 打开 | 点击那一刻 `URL.createObjectURL(new Blob([html]))` 生成 blob URL |
| 与静态书的关系 | 两套数据。静态书跟 git 与部署走，上传书只跟这台设备走 |
| 元信息 | 上传弹框内可编辑书名 / 简介 / 分类 / 标签 |
| 上限 | 单文件 8MB（`BOOKS_UPLOAD_MAX_BYTES`） |
| **不做** | 不进云同步、不进 JSON 备份、不上传服务器 |

**关键实现约束**：`entry` 字段对上传书**恒为空**，blob URL 绝不预先生成并存下来 —— blob URL 生命周期跟着文档走，刷新后旧 URL 全部指向死资源。必须在**点击那一刻**现生成（`BooksView.resolveUrl`）。

### 14.3 QA 踩到的两个"假阴性"陷阱

写目视验证脚本时踩的坑，方法论上有普遍价值：

1. **程序化设 `scrollTop` 不触发 `scroll` 事件。** 浏览器只在真实用户操作或显式 `dispatchEvent` 时派发。QA 用 `evaluate` 设 `scrollTop` 会得到「书签永远是空」的**假阴性** —— 功能其实好的。脚本改为显式 `dispatchEvent(new Event('scroll'))` 后通过。
   *补充*：`page.mouse.wheel` 在这里也不行，因为滚动容器在侧边栏而非 iframe 中心，滚轮落不上去。

2. **`el-input` 的 `data-testid` 透传给内部 `input`**，不在包装层上。选择器要写 `[data-testid="bk-search"]`，不能套 `.el-input__inner` 之前的包装层。

### 14.4 实施中修掉的两个真 bug

| Bug | 现象 | 根因 | 修法 |
|---|---|---|---|
| 上传弹框关闭后遮罩残留 | 关闭后**全页点击失效** | `BaseDialog` 没有显示开关，它**总是渲染** `.bd-overlay`（`position:fixed` 铺满视口），必须调用方 `v-if` 挂载 | `BooksView` 加 `v-if="uploadOpen"` |
| 同一本书在多个分区重复 | 收藏 + 最近 + 全部 三处都出现 | 去重只做了「顶部分区 vs 全部书籍」，漏了「收藏 vs 最近阅读」 | 三处统一去重，优先级 收藏 > 最近 > 全部，且顶部分区也遵守筛选条件 |
| **书签随机丢失** | 快速进书后马上滚动，进度条不出现 | scroll 监听挂在 `setTimeout(350ms)` 里，**绑定前的滚动没有任何事件**。iframe 加载瞬间用户已经在翻页就命中这个窗口 | 绑定完成后**立即 `readPosition()` 补采一次**；600ms 后再检查容器是否被异步替换（`isConnected`）并重绑 |
| 进度条不像进度条 | 「已读 55%」被拉满卡片整行宽，像一条灰条 | flex 子项默认 `align-self: stretch` | `.bk-progress` 加 `align-self: flex-start`（实测胶囊 66px / 卡片 275px） |

### 14.5 QA 稳定性：别用 `deleteDatabase` 做状态隔离

原先 QA 开头用 `indexedDB.deleteDatabase('easy-web-tab')` 清残留，**结果不可靠**：

SPA 页面仍持有 IDB 连接 → 触发 `onblocked` → Promise 提前 resolve（库其实没删掉）→ reload 后状态不确定。表现为同一份代码 QA **时灵时不灵**（27/27 与 24/27 交替出现），一度让我以为是产品 bug。

**正确做法**：`browser.newContext({ storageState: { cookies: [], origins: [] } })` —— playwright 每个新 context 天然是全新存储，不需要手动清。

另外把等 iframe 的固定 `sleep(2500)` 换成 `waitForFunction` 轮询，把等书签的 `sleep` 换成 `waitForSelector`：scroll 事件 → 800ms 空闲计时 → 300ms 防抖落盘 → Vue 渲染，这三段定时器叠加起来会超过任何写死的值。

改完后**连跑三次均 27/27**。
